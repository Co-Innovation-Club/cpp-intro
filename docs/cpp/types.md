# 数据类型

每一份数据都有类型（type）。编译器必须先知道一个值的类型，才知道它能表示多大、能参与哪些运算、结果又是什么类型。

C++ 的基本类型有三类：字符（`char`）、整数（`int`）和浮点数（`double`）。前面几章的变量、表达式，底层都建立在它们之上。这一章要讲的不是语法细节，而是每种类型的**边界**——竞赛里绝大多数“莫名其妙”的错误，都是某个值悄悄越过了它的类型边界。

## 字符类型

字符类型用 `char` 声明，表示单个字符。

```cpp
char c = 'B';
```

字符常量必须放在单引号里。`char` 占一个字节（8 位）。C++ 把它当整数处理，所以本质上，`char` 就是一个宽度为一个字节的整数：每个字符对应一个整数，由 ASCII 码规定，比如 `B` 对应 `66`。既然它按整数处理，在范围内整数和字符就可以互换，也可以参与算术运算。

```cpp
char a = 'B';          // 等同于 char a = 66;
char b = 'C';          // 等同于 char b = 67;
cout << a + b << '\n'; // 输出 133
```

上面 `a + b` 就是两个整数相加。能这么用，是因为从 C 继承下来的传统，`char` 在参与运算时会先提升为 `int`（见后面的“整数类型的运算”）。

竞赛里这套对应关系用得很多。判断一个字符是不是小写字母、把字母映射到 `0` 到 `25` 的下标，都是直接做减法：

```cpp
char ch = s[i];
if (ch >= 'a' && ch <= 'z')
    int idx = ch - 'a';   // 'a' 对应 0，'z' 对应 25
```

### 符号性

`char` 到底等于 `signed char` 还是 `unsigned char`，**由编译器决定**，标准没规定。多数平台上 `char` 是有符号的，范围 `-128` 到 `127`；也有些平台是无符号的，范围 `0` 到 `255`。两种范围都能覆盖 `0` 到 `127` 的 ASCII 字符，所以平时看不出区别。

```cpp
signed char c;   // -128 到 127
unsigned char c; // 0 到 255
```

一旦依赖 `char` 去存大于 `127` 的值，或者指望它一定是负数，代码就不可移植了。这属于实现相关（implementation-defined）行为，**不要依赖**。需要明确范围时，写 `signed char` 或 `unsigned char`。

这点和 `int` 不同：`int` 一定等同于 `signed int`，不存在“取决于系统”的说法。

### 转义字符

单引号本身也是字符，要表示它必须用反斜杠转义。

```cpp
char t = '\'';
```

反斜杠开头的写法主要用来表示那些无法直接打印的控制字符，它们同样是字符类型的值。

- `\a`：警报，终端会响铃或闪烁。
- `\b`：退格，光标回退一格但不删除字符。
- `\f`：换页符，现代系统上行为已接近 `\v`。
- `\n`：换行符。竞赛里输出换行一律用它，理由见《基本语法》。
- `\r`：回车符，光标移回本行开头。
- `\t`：制表符，光标移到下一个制表位，通常是下一个 8 的倍数。
- `\v`：垂直分隔符，光标移到下一行的同一列。
- `\0`：空字符（null），表示没有内容，它的值为 `0`。

字符还能写成八进制或十六进制的形式。

- `\nn`：八进制写法，`nn` 是八进制值。
- `\xnn`：十六进制写法，`nn` 是十六进制值。

```cpp
char x = 'B';
char x = 66;
char x = '\102'; // 八进制
char x = '\x42'; // 十六进制
```

这四种写法完全等价，都是整数 `66`。实际写代码时用 `'B'` 最直观，转义写法留给那些没法直接敲出来的字符。

## 整数类型

整数用 `int` 声明。这是竞赛里出现频率最高的类型，也是坑最多的类型。

### 简介

```cpp
int a;
```

`int` 的宽度由实现决定，常见是 4 个字节（32 位），也可能是 2 个字节或 8 个字节。**在竞赛平台上，可以把 `int` 当成 32 位**，也就是 4 个字节：

| 宽度 | 取值范围 |
| --- | --- |
| 16 位 | -32,768 到 32,767 |
| 32 位 | -2,147,483,648 到 2,147,483,647 |
| 64 位 | -9,223,372,036,854,775,808 到 9,223,372,036,854,775,807 |

记住 32 位那一行就够了：`int` 的上限约 **21 亿**（2,147,483,647）。

这个数字是竞赛里最重要的一条线。题目里一旦出现“两个数相乘”“求和”，先估一下上界：**只要可能超过 21 亿，就必须换 `long long`**。比如 `n` 到 `10^5`、每个数到 `10^9`，求和的上界是 `10^14`，用 `int` 存结果必然溢出，答案是错的，但程序不会报错——这是最让人难受的一类错。

### signed 与 unsigned

`signed` 表示类型带正负号；`unsigned` 表示不带符号，只能表示零和正整数。`int` 默认带符号，所以 `int` 等同于 `signed int`，`signed` 一般省略。

```cpp
signed int a;
// 等同于
int a;
```

加上 `unsigned`，同样长度的内存能表示的最大值大约翻一倍。

```cpp
unsigned int a;
```

`int` 可以省略，所以也可以写成 `unsigned a;`。

不过竞赛里**不建议随手用 `unsigned`**，原因下面会讲。真正绕不开的无符号类型只有一个：`size_t`。

### 整数的子类型

如果 `int` 用 4 个字节表示一个小整数，有点浪费；而有些场合 8 个字节还不够。为了微调范围，C++ 在 `int` 之外提供了三个整数子类型。

- `short int`（简写 `short`）：宽度不多于 `int`，一般是 2 个字节，范围 -32768 到 32767。
- `long int`（简写 `long`）：宽度不少于 `int`，至少 4 个字节。
- `long long int`（简写 `long long`）：宽度多于 `long`，至少 8 个字节。

```cpp
short int a;
long int b;
long long int c;
```

`short`、`long`、`long long` 默认都带符号，也可以加 `unsigned`。`int` 都可以省略：

```cpp
short a;
unsigned short a;

long b;
unsigned long b;

long long c;
unsigned long long c;
```

竞赛里对这三个的态度很明确：

- `long` 基本不用。它在不同平台上一个可能是 4 字节、一个是 8 字节，行为不统一；`int` 和 `long long` 就够覆盖所有需求了。
- `short` 只在非常在意内存时才有价值（比如开了上百万个元素的数组）。现代竞赛题很少卡这点内存，用 `int` 更省心。
- **`long long` 是必须熟练掌握的**。它至少 8 个字节，范围大约 `-9.2 × 10^18` 到 `9.2 × 10^18`。

`long long` 的范围（约正负 9.2 × 10^18）有多够用？`10^18` 量级的数在里面，`10^9 × 10^9` 这种乘积也在里面。竞赛里常见的错误写法是拿 `int` 算 `n * (n + 1) / 2`（`n` 到 `10^6` 就得用 `long long`），正确做法是让中间结果也走 64 位：

```cpp
int n;
long long sum = 1LL * n * (n + 1) / 2;   // 先乘 1LL，把整个表达式拉到 64 位
```

上面那个 `1LL *` 是竞赛里的固定套路，后面讲字面量后缀时会解释它为什么必须写在**最前面**。

### 整数类型的极限值

每种类型能表示的最大值、最小值，标准库给了对应的常量，定义在 `<climits>` 里（等价于 C 的 `<limits.h>`，只是名字进了 `std`）。

- `SCHAR_MIN`、`SCHAR_MAX`：`signed char` 的最小值、最大值。
- `SHRT_MIN`、`SHRT_MAX`：`short` 的最小值、最大值。
- `INT_MIN`、`INT_MAX`：`int` 的最小值、最大值。
- `LONG_MIN`、`LONG_MAX`：`long` 的最小值、最大值。
- `LLONG_MIN`、`LLONG_MAX`：`long long` 的最小值、最大值。
- `UCHAR_MAX`、`USHRT_MAX`、`UINT_MAX`、`ULONG_MAX`、`ULLONG_MAX`：各无符号类型的最大值。
- `SIZE_MAX`：`size_t` 能表示的最大值。

用它们比手写数字安全，也不会看错位数：

```cpp
cout << INT_MAX << '\n';    // 2147483647
cout << LLONG_MAX << '\n';  // 9223372036854775807
```

竞赛里这些常量最常见的用途是**当“无穷大”**。求最短路、做区间 DP 时经常需要一个比任何合法答案都大的初值，可以这么写：

```cpp
const int INF = 1e9;              // 10^9 + 7 这类题目里够用，还能加两次不溢出
const long long INFLL = 4e18;     // 64 位版本的"无穷大"
```

用 `INT_MAX` 当无穷大反而要小心：`INT_MAX + 1` 会溢出。所以惯用 `1e9`（或 `0x3f3f3f3f` ≈ 1.06 × 10^9）当 `int` 的无穷大——它离上限还差得远，做两次加法都安全。

### 整数的进制

整数默认按十进制书写。八进制用前缀 `0`，十六进制用前缀 `0x` 或 `0X`。

```cpp
int a = 012;    // 八进制，等于十进制的 10
int b = 0x1A2B; // 十六进制，等于十进制的 6699
```

`0b` 前缀表示二进制数。它从 C++14 起是标准语法，不再依赖编译器扩展。

```cpp
int x = 0b101010;   // 二进制，等于十进制的 42
```

**进制只是书写方式，不影响存储**。所有整数在内存里都是二进制，跟你怎么写无关，不同进制还能混着用，`10 + 015 + 0x20` 是合法表达式。

需要按进制输出时，`cout` 有对应的操纵符，但要记住它是**粘性**的——设一次就一直在，之后想回到十进制得重新设。

```cpp
int x = 100;
cout << hex << x << '\n';   // 64（十六进制）
cout << oct << x << '\n';   // 144（八进制）
cout << dec << x << '\n';   // 100（回到十进制）
```

想一次性输完又不想影响后面的输出，用 `printf` 更干脆，它来自 `<cstdio>`：

```cpp
int x = 100;
printf("dec = %d\n", x);    // 100
printf("octal = %o\n", x);  // 144
printf("hex = %x\n", x);    // 64
printf("octal = %#o\n", x); // 0144，带前缀
printf("hex = %#x\n", x);   // 0x64，带前缀
printf("hex = %#X\n", x);   // 0X64，前缀字母大写
```

竞赛里十六进制和 `0b` 更常出现在位运算（枚举子集、状态压缩）的掩码里，而不是输出环节。真要用到输出的地方，多半是交互题或调试打印，`printf` 的 `%#x` 足够应付。

## 浮点数类型

带小数点的数值，编译器一律解释为浮点数。浮点数用 `m × b^e` 的形式存一个数，`m` 是尾数，`b` 是基数（通常为 2），`e` 是指数。这种形式能同时兼顾精度和范围，表示很大或很小的数。

类型声明用 `float`。

```cpp
float c = 10.5;
```

`float` 占 4 个字节（32 位），能提供约 **6 到 7 位**有效数字。精度或范围不够时，还有两种更大的类型。

- `double`：占 8 个字节（64 位），能提供约 **15 到 16 位**有效数字。
- `long double`：通常是 16 个字节，精度更高，但不同编译器的实现差异较大。

竞赛里的默认选择是 `double`。理由很直接：每个 `float` 只有 6 到 7 位有效数字，稍微大一点的数（比如 `10^9` 量级）加一个小数就丢精度了；而 `double` 的 15 到 16 位足以应付绝大多数题目要求的 `1e-6` 到 `1e-9` 精度。`long double` 只在题目明确要极高精度时才用，它还更慢。

浮点数有个必须牢记的性质：**它只是近似值**。`0.1` 和 `0.2` 在二进制下都无法精确表示，所以

```cpp
double a = 0.1, b = 0.2;
if (a + b == 0.3) { /* 不会进来 */ }
```

上面这个 `if` 不会执行。`0.1 + 0.2` 的结果是 `0.30000000000000004`，不等于 `0.3`。所以**浮点数不能用 `==` 比较相等**，要设一个允许误差 `eps`：

```cpp
const double eps = 1e-9;

if (fabs(a + b - 0.3) < eps) {
    cout << "相等\n";
}
```

更推荐一个带容差的比较函数，把 `eps` 和比较逻辑收在一处：

```cpp
const double eps = 1e-9;

bool equal(double a, double b) { return fabs(a - b) < eps; }
bool less_than(double a, double b) { return a < b - eps; }   // a 明显小于 b
```

判断大小关系时也要留意：两个“应该相等”的数直接比大小，方向可能是随机的。要严格排序就按上面的 `less_than` 写，别用裸的 `<`。

`fabs` 来自 `<cmath>`（等价于 C 的 `<math.h>`），对浮点数取绝对值。

浮点数可以用科学计数法书写，用 `e` 分隔小数部分和指数部分。

```cpp
double x = 123.456e+3;  // 123.456 × 10^3
double x = 123.456e3;   // 加号可以省略
```

`e` 前后不能有空格。小数部分写成 `0.x` 或 `x.0` 时，那个 `0` 可以省略，`.3E6` 等同于 `0.3E6`。

## 布尔类型

C++ 有专门的布尔类型 `bool`，取值只有 `true`（真）和 `false`（伪），分别对应整数 `1` 和 `0`。它定义在语言里，不需要包含任何头文件。

```cpp
bool flag = false;
bool ok = true;
```

C 语言当年没有布尔类型，用整数 `0` 表示伪、所有非零值表示真。C++ 保留了这个习惯：**`bool` 和整数之间可以隐式转换**。把一个整数赋给 `bool`，非零得 `true`，零得 `false`；反过来，`true` 当 `1` 用、`false` 当 `0` 用。

```cpp
bool a = 5;      // 非零，a 为 true
bool b = 0;      // 零，b 为 false
int  x = true;   // x 为 1

if (a) {         // 等价于 if (a == true)
    cout << "yes\n";
}
```

有一个输出上的细节容易踩：`cout` 默认把 `bool` 按整数打印，输出 `1` 或 `0`，不是 `true` 或 `false`。

```cpp
cout << true << '\n';    // 1

cout << boolalpha;       // 设了这个操纵符才打印 true/false
cout << true << '\n';    // true
```

逻辑运算的结果就是 `bool`，所以 `x = (a > b)` 里的 `x` 是布尔值。竞赛里判断类变量一律用 `bool`，别拿 `int` 冒充——`int` 会让人误以为它还有别的取值。

## 字面量的类型

字面量（literal）是代码里直接写出来的值。

```cpp
int x = 123;   // x 是变量，123 是字面量
```

编译器把字面量也写进内存，所以同样得给它定类型。默认规则是这样的：十进制整数字面量（比如 `123`）是 `int`；如果超出 `int` 范围，按 `long`、`unsigned long`、`long long`、`unsigned long long` 的顺序往上找第一个装得下的类型。小数（比如 `3.14`）一律是 `double`。

这套“自动往上找”的规则听着省事，实际用起来**不要依赖**。原因有两个：一是类型由数值大小决定，同一个表达式改个常量就可能改变运算的宽度，行为不稳定；二是它可能悄悄跳到无符号类型上。竞赛里更常见的写法是显式加后缀，把类型钉死。

## 字面量后缀

后缀用来强行指定字面量的类型。

```cpp
int x = 123L;   // long
```

小写 `l` 效果一样，但**建议一律写大写的 `L`**，因为 `123l` 和 `1231` 在等宽字体里几乎分不出来。八进制、十六进制也能加后缀，如 `020L`、`0x20L`。

常用的后缀如下：

| 后缀 | 作用 |
| --- | --- |
| `f`、`F` | `float` 类型，如 `3.14f` |
| `l`、`L` | 整数是 `long int`，小数是 `long double` |
| `ll`、`LL` | `long long`，如 `3LL` |
| `u`、`U` | `unsigned int`，如 `15U`、`0377U` |

`u` 可以和别的整数后缀组合，大小写和顺序都无所谓，`10UL`、`10ULL`、`10LLU` 都合法。

```cpp
long long      a = 1234LL;
unsigned long long b = 1234ULL;

float      x = 3.14f;
double     y = 3.14;
long double z = 3.14L;
```

### `1LL` 为什么总写在最前面

竞赛里最该记住的一条是 `LL`，而且要知道它必须加在**整个表达式里第一个算术操作数**上。看这段：

```cpp
int n = 100000;
long long wrong = n * (n + 1);         // 错：右边是 int 运算，先溢出，再赋给 long long
long long right = 1LL * n * (n + 1);   // 对：n 先被提升为 long long，整体按 64 位算
```

`wrong` 之所以错，是因为赋值是按“先算右边、再转换”的顺序进行的。`n * (n + 1)` 在右边独立求值，两个操作数都是 `int`，结果也是 `int`，`10^5 × 10^5 + 10^5` 早就超过 21 亿了，溢出已经发生。等到把溢出的结果赋给 `long long` 时，坏掉的数值再也不会变回来。

正确的写法是让表达式**从第一个操作数起**就是 64 位。写成 `1LL * n` 之后，`n` 被提升为 `long long`，后续相乘、相加全在 64 位里进行。

同样的错误在位移里也很常见：

```cpp
long long bad  = 1 << 40;      // 错：1 是 int，左移 40 位是未定义行为
long long good = 1LL << 40;    // 对：1LL 是 long long，结果约 1.1 × 10^12
```

`int` 只有 32 位，把 `1` 左移 40 位属于未定义行为（见下一节）。`1LL << 40` 是竞赛里表示 `2^40` 这种大常量的标准写法，类似的还有用 `1LL << k` 生成位掩码。

## 溢出

每种类型都有取值范围的上下界。存放的数值越出这个范围，就需要更多二进制位来表示，这就是**溢出**：超过最大值叫向上溢出（overflow），小于最小值叫向下溢出（underflow）。

溢出的处理方式，有符号和无符号**完全不是一回事**，这是本章最需要分清的一点。

### 无符号数：回绕

无符号整数的运算是**模运算**，超出范围就“回绕”，行为是标准明确规定的，可以放心依赖。

```cpp
unsigned char x = 255;
x = x + 1;
cout << (int)x << '\n';   // 0
```

`255` 的二进制是 `11111111`，加 `1` 得到 `100000000`，最高位存不进一个字节，被丢掉，剩下 `0`。

```cpp
unsigned int ui = UINT_MAX;   // 4,294,967,295
ui++;
cout << ui << '\n';           // 0
ui--;
cout << ui << '\n';           // 4,294,967,295
```

反过来也成立：`0 - 1` 会得到 `UINT_MAX`。这个性质很容易写出死循环：

```cpp
for (unsigned int i = n; i >= 0; --i) { /* 死循环 */ }
```

`i` 是 `unsigned int`，最小只能到 `0`。当 `i` 等于 `0` 时再减 `1`，得到的不是 `-1`，而是 `UINT_MAX`，循环条件 `i >= 0` 永远成立，于是无限循环下去。想从 `n` 递减到 `0`，用 `int` 当循环变量，或者把循环写成 `for (int i = n; i >= 0; --i)`。

### 有符号数：未定义行为

有符号整数溢出**不是“回绕”，而是未定义行为（undefined behavior，UB）**。

这一点必须说清楚：标准对 `int` 溢出没有规定任何结果。编译器可以假设溢出不会发生，并据此做优化——于是同一段代码换个优化等级、换个编译器，行为都可能不同。**绝对不要依赖有符号溢出“变成负数”或“绕回去”**。

```cpp
int x = INT_MAX;
x = x + 1;   // 未定义行为，不是 -2147483648
```

实践中的后果不止是数值不对。因为编译器认为“`int` 变量加下去不会溢出”，它可能把 `for (int i = 0; i <= n; i++)` 这种循环当成一定会结束的循环去优化，`n` 恰好等于 `INT_MAX` 时行为就无法预料了。

结论只有一句：**有符号溢出必须靠设计规避，不能靠回绕来“利用”它**。真需要回绕效果，用 `unsigned`。

### 避免溢出

最有效的办法是在写表达式之前先估上界，而不是等错了再回头查。

第一步是估数值大小。题目给的约束通常就写明了范围，把最坏情况代进去算一遍：`n` 到 `10^5`、每个数到 `10^9`，那“求和”的上界是 `10^14`，必须用 `long long`；`n` 到 `10^6`，那 `n × n` 就是 `10^12`，同样得升到 64 位。

第二步是检查**中间结果**，而不只是最终结果。上面的 `n * (n + 1)` 就是典型：变量声明成 `long long` 也没用，因为溢出发生在赋值之前。

还有一类容易漏的地方是二分查找的取中点：

```cpp
int l = 0, r = INT_MAX;
int mid = (l + r) / 2;          // 危险：l + r 可能溢出
int mid = l + (r - l) / 2;      // 安全：差值不会超过 r 的范围
```

`(l + r)` 是两个 `int` 相加，可能溢出；写成 `l + (r - l) / 2` 就不会。这是竞赛里的标准写法，值得直接背下来。

反过来比较时，也要注意别用“算完再看有没有超”的思路：

```cpp
unsigned int ui, sum;

// 错：sum + ui 已经回绕了，永远不会大于 UINT_MAX
if (sum + ui > UINT_MAX) too_big();

// 对：把加法移到另一边，用减法判断
if (ui > UINT_MAX - sum) too_big();
```

另一种典型错误是拿无符号数做减法后判断正负：

```cpp
unsigned int i = 5, j = 7;
if (i - j < 0) cout << "negative\n";   // 永远不会输出
else           cout << "positive\n";   // 会走这里
```

`i - j` 的结果也是无符号类型，最小值是 `0`，不可能小于 `0`，所以只会走 `else`。想比较大小就直接比：`if (j > i)`。

## sizeof 运算符

`sizeof` 返回某个类型或某个值占用的字节数。参数可以是类型，也可以是变量或具体的值。

```cpp
int x = sizeof(int);   // 类型：通常是 4

int i;
sizeof(i);             // 变量：与上一行结果相同

sizeof(3.14);          // 数值：浮点字面量是 double，所以返回 8
```

**`sizeof` 的返回值类型是 `size_t`，一个无符号整数类型**。这是它的关键特性，也是它的坑所在。

大小关系里混进 `size_t`，符号问题就来了。看下面这段：

```cpp
int a = -5;
if (a < sizeof(int)) {   // 判断为假
    // 不会执行
}
```

`a` 是 `int`（有符号），`sizeof(int)` 是 `size_t`（无符号）。混合运算时，有符号的 `a` 会被转成无符号，`-5` 变成了一个接近 `SIZE_MAX` 的巨大正数，于是 `a < sizeof(int)` 为假。这正是上一节说的“有符号与无符号混合运算”的典型陷阱。

所以有两条实用建议：**循环变量、下标、计数变量统一用 `int` 或 `long long`，别用 `size_t`**；把 `sizeof` 的结果和 `int` 比较时，先转成同一类型再比。`size_t` 真正躲不开的地方是容器的 `size()`（见后面的“混合类型的运算”）。

输出 `size_t` 时，`cout` 会自己认出来，直接写就行。非要用 `printf`，用 `%zu`（或 `%zd`）：

```cpp
printf("%zu\n", sizeof(int));
```

`sizeof` 在竞赛里最实际的用途是求数组元素个数：

```cpp
int a[100];
int n = sizeof(a) / sizeof(a[0]);   // 100
```

用 `vector` 时不需要这个，`a.size()` 直接给元素个数。

## 类型的自动转换

很多情况下 C++ 会自动转换类型。这些规则本身不复杂，但会把前面几节的坑串起来，所以值得单独看一遍。

### 赋值运算

赋值运算符会把右边的值转成左边变量的类型。

**（1）浮点数赋给整数变量。** 直接**丢弃小数部分**，不是四舍五入。

```cpp
int x = 3.14;    // x 是 3
int y = 12.99;   // y 是 12，不是 13
```

小数部分被整个扔掉，所以这种赋值要尽量避免。

**（2）整数赋给浮点变量。** 自动转为浮点数。

```cpp
double y = 12 * 2;   // y 是 24.0
```

**（3）窄类型赋给宽类型。** 整数会做类型提升，比如 `char`、`short` 参与运算或赋给 `int` 时先提升为 `int`。

**（4）宽类型赋给窄类型。** 会截值（truncation），多余的二进制位被砍掉，结果难以预料。

```cpp
int i = 321;
char ch = i;   // ch 是 65
```

`321` 的二进制是 `101000001`，共 9 位；`char` 只放得下 8 位，于是丢掉最高位，留下 `01000001`，也就是十进制的 `65`（字符 `'A'`）。浮点赋给整数也一样，小数部分直接被截掉：

```cpp
double pi = 3.14159;
int i = pi;    // i 是 3
```

### 混合类型的运算

不同类型的值一起运算，必须先统一类型。规则是：

- 整数与浮点数混合时，整数转为浮点数。
- 不同的浮点类型混合时，宽度小的转为宽度大的（`float` → `double` → `long double`）。
- 不同的整数类型混合时，宽度小的提升为宽度大的；**当有符号和无符号相遇时，有符号那个会被转成无符号**。

最后一条是前面几个坑的共同来源。把 `int` 和 `size_t` 放在一起，`int` 就被当成无符号解释了，负数会变成一个巨大的正数。这也是为什么标准容器要特别小心：

```cpp
vector<int> v = {1, 2, 3, 4, 5};

// 危险：i 是 int，v.size() 是 size_t
for (int i = 0; i < v.size(); i++) { /* ... */ }

// 安全：全程用 int 存长度
int n = v.size();
for (int i = 0; i < n; i++) { /* ... */ }
```

`i < v.size()` 里 `i` 会被转成 `size_t`。上面这段因为是正向循环，`i` 始终非负，看不出问题；但如果循环里出现 `i - 1`、或者循环变量真可能变成负数，`-1` 会被当成 `SIZE_MAX`，程序直接跑飞。

实用结论：**尽量不让有符号数和无符号数混着算**。容器长度、下标这类值，读到 `int` 或 `long long` 变量里再用。

### 整数类型的运算

两个同类型的整数运算，结果一般还是同一类型。但有一个例外：**宽度小于 `int` 的类型，运算结果会自动提升为 `int`**。

```cpp
unsigned char a = 66;
if ((-a) < 0) cout << "negative\n";   // 会输出 negative
else          cout << "positive\n";
```

`a` 是无符号字符，看起来不可能小于 `0`，但 `-a` 已经不是 `unsigned char` 了——它先被提升为 `int`，成了 `-66`，于是判断成立。同样的道理：

```cpp
unsigned char a = 1, b = 255, c = 255;
if ((a - 5) < 0)  cout << "yes\n";   // 输出 yes，a - 5 提升为 int，得到 -4
if ((b + c) > 300) cout << "yes\n";  // 输出 yes，b + c 提升为 int，得到 510
```

两个条件都成立。这里“提升为 `int`”帮了忙：如果真按 8 位无符号算，`a - 5` 会回绕成 `252`，`b + c` 会回绕成 `254`，两个判断都会反过来。记住这条规则，遇到 `char`、`short`、`unsigned char` 参与的计算，先在心里把它们提升成 `int` 再看。

### 函数

函数的参数和返回值，也会自动转成函数定义里指定的类型。

```cpp
int dostuff(int, unsigned char);

char m = 42;
unsigned short n = 43;
long long c = dostuff(m, n);   // m、n 会先转成 int 和 unsigned char
```

返回值同理：

```cpp
char func() {
    int a = 42;
    return a;   // 转成 char 返回
}
```

这也是竞赛里一个不大不小的坑：函数返回类型写成 `int`，里面算出的却是需要 64 位的值，溢出在 `return` 那一刻就发生了。写函数时返回类型按“最坏情况”取，拿不准就用 `long long`。

## 类型的显式转换

与其指望自动转换的规则，不如自己写清楚要转成什么。这就是显式转换。

C++ 提供了 `static_cast`，写法是把目标类型放进尖括号：

```cpp
static_cast<int>(3.14)
```

它和 C 风格的圆括号写法作用是同一个事情：

```cpp
(int)3.14            // C 风格
static_cast<int>(3.14)   // C++ 风格
```

两者都能把值转成指定类型，但 C++ 更推荐 `static_cast`，理由有两点：一眼能看出这是在做转换，不会被误认为函数调用或运算；而且它只允许编译器认为合理的转换，`(int)` 那种写法则几乎什么都能转，出错时编译器也不拦。它来自语言本身，不用包含头文件。

看两个实际例子：

```cpp
unsigned char ch = 66;
static_cast<unsigned char>(ch);      // 转成无符号字符类型

long y = static_cast<long>(10) + 12; // 把 10 显式转成 long
```

上面的转换其实不必要——赋值运算符本来就会把右边转成左边的类型。显式转换真正有用的是**表达式内部**，竞赛里最典型的是整数除法：

```cpp
int a = 7, b = 2;

double wrong = a / b;                      // 3.0：两个 int 相除，先得到 3，再转 double
double right = static_cast<double>(a) / b; // 3.5：a 先转 double，除法按浮点做
```

第一种写法是最常见的“答案总是差的”来源：`a / b` 是两个 `int` 的除法，`3.5` 的小数部分被丢掉，转成 `double` 也不会回来。第二种只要把**其中一个操作数**转成 `double`，另一个会自动跟上，整个除法就按浮点进行。

`(double)a / b` 和 `static_cast<double>(a) / b` 效果完全一样，竞赛里两种都见得到。选一种统一写下去就行，别在同一份代码里混着用。

显式转换不能解决溢出，也不能让浮点数的精度变好，它只改变值的类型。把它当成“说明意图”的工具，而不是“修补错误”的工具。

## 可移植类型

`short`、`int`、`long` 的宽度依赖具体实现，换台机器就可能变。需要精确宽度时，`<cstdint>`（等价于 C 的 `<stdint.h>`）提供了一批长度确定的类型别名。

**（1）精确宽度类型**，宽度完全确定。

- `int8_t`、`int16_t`、`int32_t`、`int64_t`：8、16、32、64 位有符号整数。
- `uint8_t`、`uint16_t`、`uint32_t`、`uint64_t`：对应宽度的无符号整数。

这些是别名，具体指向哪个底层类型由编译器决定。比如某个平台 `int` 是 32 位，`int32_t` 就指向 `int`；如果 `long` 是 32 位，那 `int32_t` 就指向 `long`。

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int32_t x32 = 45933945;
    cout << x32 << '\n';
    return 0;
}
```

**（2）最小宽度类型**，保证宽度不少于指定位数：`int_least8_t`、`uint_least16_t`、`int_least64_t` 等。

**（3）最快的最小宽度类型**，在满足宽度要求的前提下取运算最快的类型：`int_fast8_t`、`uint_fast32_t` 等。某些机器对特定宽度的数据运算更快，这类别名就是为此准备的。

**（4）能存放指针的整数类型**：`intptr_t`（有符号）、`uintptr_t`（无符号）。

**（5）最大宽度整数类型**：`intmax_t`、`uintmax_t`，宽度比 `long long` 和 `unsigned long` 还大。

这些类型在竞赛里用得很少——`int` 和 `long long` 已经覆盖了全部需求，而 `int32_t` 这类名字更长，写起来还费手。它们的价值有两个：一是读别人的代码时不至于不认识；二是遇到明确要求“输出一个 32 位无符号整数”的题目，`uint32_t` 能准确表达意图。写自己的代码，仍然优先 `int` 和 `long long`。
