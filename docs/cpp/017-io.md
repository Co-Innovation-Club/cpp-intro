# 输入输出

程序与外部环境的交互依靠**输入输出**（I/O）：输入是从外部读取数据，输出是把结果送出。竞赛程序与外界的全部交互是读取题目给定的数据、写出答案。

C++ 的 I/O 有两组接口：标准库的 `cin` / `cout`（在 `<iostream>` 中定义），以及 `scanf` / `printf` 这组格式化输入输出函数（C++ 标准库同样提供它们，在 `<cstdio>` 中声明）。`<cstdio>` 是 C++ 标准库头文件，其中声明了格式化输入输出、字符输入输出、文件读写这组函数。**竞赛代码默认使用 `cin` / `cout`**：书写更短、类型自动识别。只有在数据量特别大或需要精细格式控制时，才改用 `printf` / `scanf`。

## 缓存和字节流

I/O 函数并非每次都直接访问外部设备，中间经过一层**缓存**（buffer）。

以文件为例：磁盘的读写速度比内存低几个数量级，如果程序每输出一个数字就写一次磁盘，大部分时间都消耗在等待设备上。标准库的做法是，打开一个文件（或标准输入输出）时在内存中为其分配一块缓存区。写数据时先写入缓存，填满后一次性交给设备；读数据时先向设备读取一大块放入缓存，程序再从缓存中取，取空后再读取下一块。一次传输一大块数据的开销低于逐次传输少量数据。

数据按先后顺序依次传输的模型称为**流**（stream）。C++ 的 `cin` 是输入流，`cout` 是输出流，`scanf` / `printf` 背后是同一套流概念。

流有一个重要性质：**读过的数据不再保留**。字符从流中被取走之后，再次读取只能获得后面的内容。因此先 `cin >> x` 再 `cin >> y`，得到的是下一个数据。

`cin` / `cout` 与 `scanf` / `printf` 属于两套独立的输入输出实现，各有自己的缓冲区。默认情况下两者保持同步，使混用时读写位置一致；该同步默认是开启的，代价是每次输入输出操作都要多做一层缓冲协调。竞赛代码通常关闭该同步，见“输入加速”。

## cin：标准输入

`cin` 是“字符输入流”（character input），配合右移运算符 `>>` 把数据从流里取出来。它定义在 `<iostream>` 里，被 `bits/stdc++.h` 一并包含。

### 基本用法

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int age;
    double height;

    cin >> age >> height;       // 一次读入两个值

    cout << age << ' ' << height << '\n';
    return 0;
}
```

`>>` 在这里读作“提取”，把右侧变量所需的数据从流中取出并写入。它与 `cout` 的 `<<` 对应。`>>` 的用法有三点：

- **类型自动识别**。变量是 `int` 就按整数读，是 `double` 就按小数读，类型由变量自身决定，不需要在语句中写出类型标记。
- **直接写变量名**。`>>` 右侧是变量本身，写 `cin >> age` 即可，不需要在变量名前加取地址运算符 `&`。
- **一次可以读多个**。`cin >> a >> b >> c` 从左到右依次提取，可以连续书写。

`scanf` / `printf` 需要在格式串中用占位符指定类型，并在变量前加 `&`，占位符写错或漏写 `&` 是竞赛中的常见错误，`cin` / `cout` 不存在这些问题。

`>>` 的返回值是 `cin` 本身，因此可以连续使用，也可以作为判断条件（见下文“读到数据末尾”的写法）。

### 空白符会被跳过

`cin >>` 提取数值或字符串时，会先跳过前面所有空白字符（空格、制表符、换行符），再从第一个有效字符开始，读到第一个不属于该类型的字符为止。所以下面两种输入，读出来的结果完全一样：

```text
1 -20 3.4 -4.0e3
```

```text
1
-20
3.4
-4.0e3
```

换行、多个空格、空行，`cin >>` 一律跳过。因此数据之间的空格数量不影响读取结果。

读字符串时该规则表现为：`cin >> s`（`s` 是 `string`）从第一个非空白字符开始，读到空白字符为止。它一次只能读入一个词，无法读入带空格的一整行：

```cpp
string s;
cin >> s;           // 输入 "hello world"，s 只会得到 "hello"
```

### 读到数据末尾

判题机把数据一次性交给程序，读到没有数据为止。`cin >> x` 成功时返回真、失败时（比如数据读完）返回假，所以可以这么写循环：

```cpp
int x;
while (cin >> x) {          // 一直读到没有数据为止
    cout << x << '\n';
}
```

这是读入数量不确定的数字的标准写法。等价地也可以判断 `cin.fail()` 或 `cin.eof()`，`while (cin >> x)` 的形式更短。

### cin 和 getline 混用

要读一整行（含空格），得用 `getline`：

```cpp
string s;
getline(cin, s);            // 读入一行，换行符被丢弃
```

`getline` 从流的当前位置读到换行符为止，读取换行符但不把它存入 `s`。“当前位置”是问题的关键——`cin >>` 读到数据结尾即停止，**换行符仍留在流中**：

```cpp
int n;
cin >> n;                   // 输入 "5\n"

string s;
getline(cin, s);            // s 是空字符串！流里剩的第一个字符就是 '\n'
```

此时 `s` 为空字符串。`cin >> n` 只取走 `5`，`\n` 留在流中，`getline` 读到的第一个字符即为换行符，随即结束读取。

两种改法：

```cpp
cin >> n;
cin.ignore();               // 手动吃掉那个换行符

string s;
getline(cin, s);            // 现在能正常读到一整行
```

或者用 `ws` 操纵符，读之前先把前导空白清掉：

```cpp
getline(cin >> ws, s);      // 跳过开头的空白字符再读一整行
```

两种写法都常见。`cin.ignore()` 显式丢弃一个字符，`ws` 跳过全部前导空白字符。

### 输入加速

`cin` / `cout` 的速度低于 `scanf` / `printf`，主要原因是同步：默认情况下 `cin` / `cout` 与 `scanf` / `printf` 保持同步，以保证两者混用时读取位置一致，代价是每次操作都要多做一层缓冲协调。该同步默认是开启的。

```cpp
ios::sync_with_stdio(false);
cin.tie(nullptr);
```

竞赛代码通常将这两行放在 `main` 开头。

- `ios::sync_with_stdio(false);` 关闭 `cin` / `cout` 与标准 C 输入输出缓冲区的同步。关闭之后 `cin` 和 `cout` 使用各自的缓冲，不再与另一套输入输出协调读写位置，速度快好几倍，数据量大时与 `scanf` 基本持平。竞赛程序通常不同时混用两套接口，因此这项开销可以省去。
- `cin.tie(nullptr);` 解除 `cin` 与 `cout` 的绑定。默认每次读 `cin` 之前都会强制刷新 `cout` 的缓冲，以便“先输出提示再读取输入”的交互正常显示。竞赛程序没有这种交互需求，解除绑定可以省去这些刷新。输出量大时，该设置同样有效。

使用这两行时有两条约束：

- **关闭同步之后，不能再混用 `scanf` / `printf` / `getchar` 与 `cin` / `cout`**。两套缓冲独立管理，读取位置会不一致。要么全程使用 `cin` / `cout`，要么全程使用 `scanf` / `printf`。
- 交互题（边读边输出）中，`cin.tie(nullptr)` 之后需要输出时手动调用 `cout.flush()`。

如果关闭同步后仍不满足时间要求，最后的选择是手写快读（见“getchar()，putchar()”一节）。

## printf

`printf`（print formatted，格式化打印）是 C++ 标准库提供的一个格式化输出函数，在 `<cstdio>` 中声明。它按格式字符串输出：格式串中的普通字符原样输出，占位符（以 `%` 开头）指定对应数据的类型与输出形式，后面的参数依次填入各占位符。它不自动换行，格式控制的表达更紧凑。

`cout <<` 的用法，以及 `printf` 的完整占位符、宽度、精度控制，已经在《基本语法》一章讲过，这里只说明竞赛中的定位：**需要格式控制时用 `printf`，其余情况用 `cout`**。

最常用的是浮点数定精度：

```cpp
printf("%.2f\n", ans);      // 保留两位小数
```

`%.2f` 中的 `.2` 指定小数点后保留两位，`f` 表示按浮点数输出。固定小数位、按宽度对齐、按十六进制输出这几项需求，`cout` 需要多个操纵符，`printf` 用一个格式串即可表达。**混用 `printf` 和 `cout` 时不要关闭同步**，否则两边缓冲不一致，输出顺序会错乱。

## scanf

### 基本用法

`scanf` 从标准输入读数据，原型也在 `<cstdio>`。第一个参数是格式字符串，里面放占位符，后面跟对应数量的变量地址：

```cpp
scanf("%d", &i);
```

变量前面**必须加 `&`**（`&` 是取地址运算符，字符数组除外），因为 `scanf` 需要的是变量的地址，而不是变量的值——它要把读到的数据写进那块内存。漏掉 `&` 时，编译往往仍能通过，运行时会向该值所表示的地址写入数据，属于典型的未定义行为。

一次读多个：

```cpp
scanf("%d%d%f%f", &i, &j, &x, &y);
```

格式字符串 `%d%d%f%f` 表示前两个是整数、后两个是浮点数，输入 `1 -20 3.4 -4.0e3` 会依次填进 `i`、`j`、`x`、`y`。`scanf` 同样会跳过数值前的空白字符，输入分成几行也没关系。

和 `cin >>` 一样，它会从上次停下的地方继续往下读，遇到不属于当前占位符的字符就停。

`scanf` 的返回值是成功读取并赋值的变量个数；一个都没读到返回 `0`，读到输入结束返回常量 `EOF`（end of file，表示后面没有数据可读）。该返回值可以用来判断输入是否结束，但写循环要先判断返回值，形式比 `while (cin >> x)` 繁琐：

```cpp
int x;
while (scanf("%d", &x) != EOF) {    // 读到结尾为止
    // ...
}
```

`EOF` 通常定义为 `-1`。

### 占位符

`scanf` 的占位符如下，每个占位符对应后面一个参数的类型：

- `%c`：单个字符。
- `%d`：`int` 类型的整数。
- `%lld`：`long long` 类型的整数。
- `%f`：`float` 类型的浮点数。
- `%lf`：`double` 类型的浮点数。
- `%Lf`：`long double` 类型的浮点数。
- `%s`：字符串，从第一个非空白字符读到空白字符为止，末尾自动补 `'\0'`。
- `%[]`：方括号里指定一个字符集合，比如 `%[0-9]` 表示只读数字，遇到不在集合里的字符就停。

**`%f` 和 `%lf` 的区分只存在于 `scanf`**：读 `float` 用 `%f`，读 `double` 用 `%lf`；而 `printf` 输出 `float` 和 `double` 都写 `%f`。两端规则不一致，占位符用错时读到的是无意义的值。这也是竞赛代码更多使用 `cin` 的原因之一。

除了 `%c`，所有占位符都会自动跳过开头的空白字符；`%c` 不跳过，永远取当前第一个字符，哪怕它是空格。想跳过空白再读字符，就在 `%c` 前加一个空格：

```cpp
scanf(" %c", &ch);
```

输入全为字母时，加空格与否没有区别；输入中混合空格或换行时，只有加了空格的写法才不会读到空白字符。

`%s` 从第一个非空白字符开始，读到空白字符为止，因此同样无法读入带空格的一整行；而且它向字符数组写入时不检查长度，输入比数组长就会写到数组之外的内存（越界）。在 `%` 与 `s` 之间写一个整数，可以限定最多读入的字符数：

```cpp
char name[11];
scanf("%10s", name);        // 最多读 10 个字符，剩下的丢弃
```

`%10s` 中的 `10` 指定最多读入 10 个字符，超出部分的字符不会被写入 `name`。字符数组末尾还要留一个位置存放 `'\0'`，所以 `char name[11]` 搭配 `%10s` 使用。

竞赛代码通常直接使用 `string` 配 `cin`，长度由标准库管理。

### 赋值忽略符

输入格式不固定时，可以用赋值忽略符 `*`。把它加在占位符的 `%` 后面，这个占位符匹配到的内容会被丢掉，不写进任何变量：

```cpp
scanf("%d-%d-%d", &year, &month, &day);         // 只认 2020-01-01
scanf("%d%*c%d%*c%d", &year, &month, &day);     // 分隔符是什么都行
```

`%*c` 表示“读走一个字符但不存”，于是 `2020/01/01` 也能正确解析。

### 与 cin 的对照

| 场景 | `cin` / `cout` | `scanf` / `printf` |
| --- | --- | --- |
| 类型指定 | 自动识别，不写占位符 | 必须写对 `%d`、`%lf` |
| 取地址 | 不需要 | 变量前要加 `&` |
| 读一个词 | `cin >> s`，`string` 自动管长度 | `%s` 要自己保证数组不越界 |
| 读一整行 | `getline(cin, s)` | `fgets` 或 `%[^\n]` |
| 格式控制 | 需要多个操纵符 | `%.2f`、`%5d` 一个格式串完成 |
| 速度 | 关同步后可接受 | 更快，超大数据量更稳 |

**默认使用 `cin` / `cout`；需要定精度或面对极端数据量时改用 `printf` / `scanf`，两套接口不要混用**。

## sscanf

`sscanf` 和 `scanf` 用法几乎一样，区别是数据来自一个字符串，而不是标准输入。它的原型在 `<cstdio>`：

```cpp
int sscanf(const char* s, const char* format, ...);
```

第一个参数是源字符串，其余和 `scanf` 相同。典型用法是先读一整行，再从中拆出几个数：

```cpp
char line[100];
fgets(line, sizeof(line), stdin);

int a, b;
sscanf(line, "%d%d", &a, &b);
```

`fgets(line, sizeof(line), stdin)` 从标准输入读入一行（含结尾的换行符）存入字符数组 `line`，最多读取 `sizeof(line) - 1` 个字符；`stdin` 表示标准输入。

用 `string` 时传 `c_str()`：

```cpp
string line;
getline(cin, line);

int a, b;
sscanf(line.c_str(), "%d%d", &a, &b);
```

`sscanf` 的源是字符串不是流，读过的内容不会消失，同一个字符串可以反复解析，这一点比 `scanf` 灵活。返回值和 `scanf` 一样，是成功赋值的变量个数。

竞赛中它常用于这类场景：输入是格式不固定的文本（比如 `1,2,3` 或者 `a=3 b=4`），先用 `getline` 读入整行，再用 `sscanf` 配合格式串提取其中的数值。

## getchar()，putchar()

（1）**getchar()**

`getchar()` 从标准输入读一个字符，不带参数，等价于 `scanf("%c", &ch)`：

```cpp
int ch = getchar();         // 注意返回类型是 int
```

它**不跳过空白字符**，读到什么就是什么。读取失败时返回常量 `EOF`（通常是 `-1`），所以返回值应当用 `int` 承接，而不是 `char`——`char` 无法同时表示 `-1` 与全部字符值，比较结果会出错。

返回的就是字符本身，所以可以直接放进循环条件。比如跳过当前行剩下的内容：

```cpp
while (getchar() != '\n')
    ;
```

数一行的长度：

```cpp
int len = 0;
while (getchar() != '\n')
    len++;
```

跳过前导空格：

```cpp
int ch;
while ((ch = getchar()) == ' ')
    ;
// 循环结束时 ch 是第一个非空格字符
```

（2）**putchar()**

`putchar(ch)` 输出一个字符，等价于 `printf("%c", ch)`。操作成功时返回该字符，失败返回 `EOF`。

（3）**手写快读**

`getchar` 逐字符读取，没有格式解析的开销，是追求极限读取速度的基础。当 `cin` 关闭同步后仍不满足时间要求时，可以手写快读函数：

```cpp
#include <bits/stdc++.h>
using namespace std;

int read() {
    int x = 0, f = 1;
    char c = getchar();

    while (c < '0' || c > '9') {        // 跳过非数字字符（含负号）
        if (c == '-') f = -1;
        c = getchar();
    }
    while (c >= '0' && c <= '9') {      // 逐位累加
        x = x * 10 + (c - '0');
        c = getchar();
    }
    return x * f;
}

int main() {
    int n = read();
    cout << n << '\n';
    return 0;
}
```

该函数逐位累加：先跳过非数字字符，遇到 `-` 记录符号，之后每读入一个数字字符就把结果乘十并加上该数字，最后乘上符号。它只处理整数。

这类手写快读在**读入量极大**（千万级整数以上）的题目中能减少运行时间，代价是代码变长、容易写错，且只支持特定类型。多数题目使用 `ios::sync_with_stdio(false); cin.tie(nullptr);` 加 `cin` 即可，快读留作最后手段。

## puts()

`puts(s)` 把字符串输出到屏幕，并**自动补一个换行**，原型在 `<cstdio>`：

```cpp
puts("Here are some messages:");
puts("Hello World");
```

写入成功返回非负整数，失败返回 `EOF`。它会自动换行、实现简单，但在 C++ 中该用途由 `cout` 承担：

```cpp
cout << "Hello World" << '\n';      // 等价，且和全书风格一致
```

竞赛代码不需要使用 `puts`，了解其存在以便在阅读他人代码时识别即可。

## gets()

`gets()` 以前用来从标准输入读一整行（连空格一起读，丢弃换行符，末尾补 `'\0'`），常和 `puts()` 配对：

```cpp
char words[81];
puts("Enter a string, please");
gets(words);            // 已废弃，不要用
```

它不检查目标数组的长度，输入比数组长就直接越界，是典型的安全漏洞。`gets` 在 C99 被标记废弃、C11 起从标准中移除，C++14 之后标准库也不再提供它。**读一整行使用 `getline(cin, s)`**，需要字符数组时使用 `fgets`。
