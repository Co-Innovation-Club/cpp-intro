# 输入输出

程序和外界打交道靠的是**输入输出（I/O）**：输入是从外部拿到数据，输出是把结果送出去。竞赛程序与外界的全部交互就是"读题面给的数据、写出答案"，所以这一章很实在。

C++ 做 I/O 主要靠两套东西：标准库的 `cin` / `cout`（来自 `<iostream>`），以及继承自 C 的 `scanf` / `printf`（来自 `<cstdio>`）。**竞赛里默认用 `cin` / `cout`**——写起来短、类型自动识别、不容易出错；只有在数据量特别大或者需要精细格式控制时，才换用 `printf` / `scanf`。本章按这个思路讲。

## 缓存和字节流

I/O 函数并不真的每次都直接和外部设备打交道，中间隔着一层**缓存（buffer）**。

以文件为例：磁盘的读写速度比内存慢好几个数量级，如果程序每输出一个数字就写一次磁盘，绝大部分时间都在等设备。标准库的做法是，打开一个文件（或标准输入输出）时就在内存里给它配一块缓存区。写数据时先攒进缓存，攒满了再一次性交给设备；读数据时先向设备要一大块放进来，程序再从缓存里取，取空了再要下一块。一次搬一大块，比零敲碎打地搬快得多。

这种"数据一段一段流过"的模式很像水流，所以叫**流（stream）**。C++ 的 `cin` 是输入流，`cout` 是输出流，`scanf` / `printf` 背后是同一套流概念。

流有个重要后果：**读过的数据就没了**。字符从流里被取走之后，重读只能拿到后面的内容，这和"读文件时想读几次读几次"完全不同。理解这一点，就能明白为什么先 `cin >> x` 再 `cin >> y`，拿到的必然是下一个数据。

还有一处工程细节：`cin` / `cout` 默认与 C 的 `stdio`（`scanf` / `printf` / `getchar` 那一套）保持同步，代价是每次操作都要多绕一圈。竞赛里通常会关掉这个同步，见下文"输入加速"。

## cin：标准输入

`cin` 是"字符输入流"（character input），配合右移运算符 `>>` 把数据从流里取出来。它定义在 `<iostream>` 里，被 `bits/stdc++.h` 一并包含。

### 基本用法

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int age;
    double height;

    cin >> age >> height;       // 一次读入两个值

    cout << age << ' ' << height << '\n';
    return 0;
}
```

`>>` 在这里念作"提取"，把右边变量该有的数据从流里取出来填进去。和 `cout` 的 `<<` 正好对应。它比 C 的 `scanf` 好在三处：

- **类型自动识别**。变量是 `int` 就按整数读，是 `double` 就按小数读，不用像 `scanf` 那样记 `%d`、`%lf` 这些占位符。占位符写错是竞赛里最常见的低级错误之一，用 `cin` 直接绕开。
- **不用取地址**。写 `cin >> age`，而不是 `scanf("%d", &age)`。`scanf` 里忘写 `&` 不报错但行为危险，`cin` 里根本没这回事。
- **一次可以读多个**。`cin >> a >> b >> c` 从左到右依次提取，写一串就行。

`>>` 的返回值是 `cin` 本身，所以能连环使用，也能当判断条件（见下文"读到数据末尾"的写法）。

### 空白符会被跳过

`cin >>` 提取数值或字符串时，会先跳过前面所有空白字符（空格、制表符、换行符），再从第一个有效字符开始，读到第一个不属于该类型的字符为止。所以下面两种输入，读出来的结果完全一样：

```text
1 -20 3.4 -4.0e3
```

```text
1
-20
3.4
-4.0e3
```

换行、多个空格、空行，`cin >>` 一概不管。这就是"数据之间有多少空格都不影响"的原因，输入格式的容错性很好。

读字符串时这条规则要留意：`cin >> s`（`s` 是 `string`）从第一个非空白字符开始，读到空白就停。所以它一次只能读一个"词"，读不了带空格的一整行：

```cpp
string s;
cin >> s;           // 输入 "hello world"，s 只会得到 "hello"
```

### 读到数据末尾

判题机把数据一次性交给程序，读到没有数据为止。`cin >> x` 成功时返回真、失败时（比如数据读完）返回假，所以可以这么写循环：

```cpp
int x;
while (cin >> x) {          // 一直读到没有数据为止
    cout << x << '\n';
}
```

这是"读入不确定个数的数字"的标准写法，比先数个数再循环省心得多。等价地也可以判断 `cin.fail()` 或 `cin.eof()`，但 `while (cin >> x)` 最简洁，推荐这么写。

### cin 和 getline 混用

要读一整行（含空格），得用 `getline`：

```cpp
string s;
getline(cin, s);            // 读入一行，换行符被丢弃
```

`getline` 从当前位置读到换行符为止，把换行符吃掉但不放进 `s`。问题就出在"当前位置"上——`cin >>` 读到数据结尾就停，**换行符还留在流里**：

```cpp
int n;
cin >> n;                   // 输入 "5\n"

string s;
getline(cin, s);            // s 是空字符串！流里剩的第一个字符就是 '\n'
```

本来想读一行文字，结果 `s` 是空的。原因是 `cin >> n` 只取走了 `5`，把 `\n` 留在了流里，`getline` 一看第一个字符就是换行，直接收工。

两种改法：

```cpp
cin >> n;
cin.ignore();               // 手动吃掉那个换行符

string s;
getline(cin, s);            // 现在能正常读到一整行
```

或者用 `ws` 操纵符，读之前先把前导空白清掉：

```cpp
getline(cin >> ws, s);      // 跳过开头的空白字符再读一整行
```

两种写法都常见，`cin.ignore()` 更直观。记住这个坑就够了。

### 输入加速

`cin` / `cout` 用着舒服，代价是比 `scanf` / `printf` 慢。默认情况下，C++ 的流要和 C 的 `stdio` 保持同步——保证 `cin` 和 `scanf` 混用时不至于读乱，代价是每次操作都要多做一层缓冲协调。

```cpp
ios::sync_with_stdio(false);
cin.tie(nullptr);
```

这两行是竞赛模板的标配，放在 `main` 开头。

- `ios::sync_with_stdio(false);` 关掉 C++ 流与 C `stdio` 的同步。`cin` 和 `cout` 从此使用自己的缓冲，速度快好几倍，数据量大时和 `scanf` 基本持平。
- `cin.tie(nullptr);` 解除 `cin` 与 `cout` 的绑定。默认每次读 `cin` 之前都会强制刷新 `cout` 的缓冲，为的是让"先提示再输入"这种交互显示正常。竞赛程序不需要这种交互感，断开绑定可以省掉一堆无谓刷新。输出量大时，这条同样重要。

用这两行要记住两条约束：

- **关掉同步之后，不能再混用 `scanf` / `printf` / `getchar` 和 `cin` / `cout`**。两套缓冲各自为政，读到的位置会对不上。要么全程用 C++ 流，要么全程用 C 函数。
- 交互题（要边读边回答）里得小心：`cin.tie(nullptr)` 之后需要输出时，要记得手动 `cout.flush()`。

如果关了同步还是不够快，最后的手段是手写快读（见"getchar()，putchar()"一节）。

## printf

`printf`（print formatted，格式化打印）来自 `<cstdio>`，等价于 C 的 `<stdio.h>` 里的同名函数。它不自动换行，格式控制能力很强。

`cout <<` 的用法，以及 `printf` 的完整占位符、宽度、精度控制，已经在《基本语法》一章讲过，这里只强调竞赛里的定位：**需要格式控制时用 `printf`，其余情况用 `cout`。**

最常用的是浮点数定精度：

```cpp
printf("%.2f\n", ans);      // 保留两位小数
```

固定小数位、按宽度对齐、按十六进制输出这几件事，`cout` 要写一堆操纵符，`printf` 一句就清楚。另外注意，**混用 `printf` 和 `cout` 时不要关同步**，否则两边缓冲不一致，输出顺序会乱。

## scanf

### 基本用法

`scanf` 从标准输入读数据，原型也在 `<cstdio>`。第一个参数是格式字符串，里面放占位符，后面跟对应数量的变量地址：

```cpp
scanf("%d", &i);
```

变量前面**必须加 `&`**（字符数组除外），因为 `scanf` 要的是变量的地址，而不是变量的值——它得把读到的数据写进那块内存。这是初学时最容易忘的地方：漏了 `&`，编译往往还能过，运行起来却会去写一个莫名其妙的内存位置，属于典型的未定义行为。

一次读多个：

```cpp
scanf("%d%d%f%f", &i, &j, &x, &y);
```

格式字符串 `%d%d%f%f` 表示前两个是整数、后两个是浮点数，输入 `1 -20 3.4 -4.0e3` 会依次填进 `i`、`j`、`x`、`y`。`scanf` 同样会跳过数值前的空白字符，输入分成几行也没关系。

和 `cin >>` 一样，它会从上次停下的地方继续往下读，遇到不属于当前占位符的字符就停。

`scanf` 的返回值是成功读取并赋值的变量个数；一个都没读到返回 `0`，读到文件结尾返回常量 `EOF`。这个返回值可以用来判断输入是否结束，但写循环要先看返回值，比 `while (cin >> x)` 啰嗦：

```cpp
int x;
while (scanf("%d", &x) != EOF) {    // 读到结尾为止
    // ...
}
```

`EOF` 通常定义为 `-1`。

### 占位符

`scanf` 的占位符如下：

- `%c`：单个字符。
- `%d`：整数（`int`）。
- `%f`：`float`。
- `%lf`：`double`。
- `%Lf`：`long double`。
- `%s`：字符串。
- `%[]`：方括号里指定一个字符集合，比如 `%[0-9]` 表示只读数字，遇到不在集合里的字符就停。

**`%f` 和 `%lf` 的差别是 `scanf` 独有的坑**：读 `float` 用 `%f`，读 `double` 用 `%lf`；而 `printf` 输出 `float` 和 `double` 都写 `%f`。两头规则不一致，记混了读出来的就是垃圾值。这也是竞赛里更推荐 `cin` 的原因之一。

除了 `%c`，所有占位符都会自动跳过开头的空白字符；`%c` 不跳过，永远取当前第一个字符，哪怕它是空格。想跳过空白再读字符，就在 `%c` 前加一个空格：

```cpp
scanf(" %c", &ch);
```

这条看着不起眼，实际很有用：输入全是字母时它没影响，而一旦混了空格或换行，加了空格的写法才不会读到一个空格。

`%s` 要特别说一句：它从第一个非空白字符开始，读到空白字符为止，所以同样读不了带空格的一整行；而且它往字符数组里写时不检查长度，输入比数组长就会越界。C 里靠限定长度缓解：

```cpp
char name[11];
scanf("%10s", name);        // 最多读 10 个字符，剩下的丢弃
```

竞赛里更省事的做法是直接用 `string` 配 `cin`，长度由标准库自己管，不用数数字。

### 赋值忽略符

输入格式不固定时，可以用赋值忽略符 `*`。把它加在占位符的 `%` 后面，这个占位符匹配到的内容会被丢掉，不写进任何变量：

```cpp
scanf("%d-%d-%d", &year, &month, &day);         // 只认 2020-01-01
scanf("%d%*c%d%*c%d", &year, &month, &day);     // 分隔符是什么都行
```

`%*c` 表示"读走一个字符但不存"，于是 `2020/01/01` 也能正确解析。

### 与 cin 的对照

| 场景 | `cin` / `cout` | `scanf` / `printf` |
| --- | --- | --- |
| 类型指定 | 自动识别，不写占位符 | 必须写对 `%d`、`%lf` |
| 取地址 | 不需要 | 变量前要加 `&` |
| 读一个词 | `cin >> s`，`string` 自动管长度 | `%s` 要自己保证数组不越界 |
| 读一整行 | `getline(cin, s)` | `fgets` 或 `%[^\n]` |
| 格式控制 | 需要操纵符，啰嗦 | `%.2f`、`%5d` 一句搞定 |
| 速度 | 关同步后可接受 | 更快，超大数据量更稳 |

结论很简单：**默认 `cin` / `cout`，需要定精度或碰到极端数据量时切到 `printf` / `scanf`，两套不要混用。**

## sscanf

`sscanf` 和 `scanf` 用法几乎一样，区别是数据来自一个字符串，而不是标准输入。它的原型在 `<cstdio>`：

```cpp
int sscanf(const char* s, const char* format, ...);
```

第一个参数是源字符串，其余和 `scanf` 相同。典型用法是先读一整行，再从中拆出几个数：

```cpp
char line[100];
fgets(line, sizeof(line), stdin);

int a, b;
sscanf(line, "%d%d", &a, &b);
```

用 `string` 时传 `c_str()`：

```cpp
string line;
getline(cin, line);

int a, b;
sscanf(line.c_str(), "%d%d", &a, &b);
```

`sscanf` 的源是字符串不是流，读过的内容不会消失，同一个字符串可以反复解析，这一点比 `scanf` 灵活。返回值和 `scanf` 一样，是成功赋值的变量个数。

竞赛里它常出现在这种场景：输入是一坨格式不定的文本（比如 `1,2,3` 或者 `a=3 b=4`），先用 `getline` 整行读进来，再用 `sscanf` 配上合适的格式串把数字抠出来。

## getchar()，putchar()

**（1）getchar()**

`getchar()` 从标准输入读一个字符，不带参数，等价于 `scanf("%c", &ch)`：

```cpp
int ch = getchar();         // 注意返回类型是 int
```

它**不跳过空白字符**，读到什么就是什么。读取失败时返回常量 `EOF`（通常是 `-1`），所以返回值应该用 `int` 承接，而不是 `char`——`char` 放不下 `-1` 和全部字符值，比较会出错。

返回的就是字符本身，所以可以直接放进循环条件。比如跳过当前行剩下的内容：

```cpp
while (getchar() != '\n')
    ;
```

数一行的长度：

```cpp
int len = 0;
while (getchar() != '\n')
    len++;
```

跳过前导空格：

```cpp
int ch;
while ((ch = getchar()) == ' ')
    ;
// 循环结束时 ch 是第一个非空格字符
```

**（2）putchar()**

`putchar(ch)` 输出一个字符，等价于 `printf("%c", ch)`。操作成功时返回该字符，失败返回 `EOF`。

**（3）手写快读**

`getchar` 逐字符读取，本身没有格式解析的负担，是"极限速度"路线的基础。当 `cin` 关了同步还是过不去时，可以手写一个快读函数：

```cpp
#include <bits/stdc++.h>
using namespace std;

int read() {
    int x = 0, f = 1;
    char c = getchar();

    while (c < '0' || c > '9') {        // 跳过非数字字符（含负号）
        if (c == '-') f = -1;
        c = getchar();
    }
    while (c >= '0' && c <= '9') {      // 逐位累加
        x = x * 10 + (c - '0');
        c = getchar();
    }
    return x * f;
}

int main() {
    int n = read();
    cout << n << '\n';
    return 0;
}
```

思路很直白：一路读到数字为止，遇到 `-` 记下符号，然后每读一个数字字符就把结果乘十加上它，最后补上符号。它只处理整数，读负数要自己判断符号位。

这类手写快读在**读入量极大**（千万级整数以上）的题里能压出不少时间，代价是代码变长、容易写错、还只能读特定类型。多数题目用 `ios::sync_with_stdio(false); cin.tie(nullptr);` 加 `cin` 就够了，快读留作最后手段。

## puts()

`puts(s)` 把字符串输出到屏幕，并**自动补一个换行**，原型在 `<cstdio>`：

```cpp
puts("Here are some messages:");
puts("Hello World");
```

写入成功返回非负整数，失败返回 `EOF`。它的好处是自动换行、实现简单，但在 C++ 里这个位置已经被 `cout` 占了：

```cpp
cout << "Hello World" << '\n';      // 等价，且和全书风格一致
```

竞赛里没有理由特意用 `puts`，知道它存在、读别人代码时认得出来即可。

## gets()

`gets()` 以前用来从标准输入读一整行（连空格一起读，丢弃换行符，末尾补 `'\0'`），常和 `puts()` 配对：

```cpp
char words[81];
puts("Enter a string, please");
gets(words);            // 已废弃，不要用
```

它不检查目标数组的长度，输入比数组长就直接越界，是经典的安全漏洞。`gets` 在 C99 被标记废弃、C11 起从标准中移除，C++14 之后标准库也不再提供它。**读一整行用 `getline(cin, s)`**，需要字符数组时用 `fgets`，别再用 `gets`。
