# 字符编码

## Unicode 简介

C 诞生时只考虑了英语，用 7 位的 ASCII 码表示字符。ASCII 的范围是 0 到 127，一百多个字符足够覆盖英文大小写字母、数字和常用符号，用一个字节（8 位）装下绰绰有余——这也正是 `char` 类型只占 1 个字节的历史原因。

ASCII 装不了别的语言。光中文就有几万个常用字，一个字节远远不够，只能一个字用多个字节表示。早期各国各写各的编码，同一串字节按不同编码读出来意思完全不同，数据一交换就乱。于是后来逐渐统一到 Unicode：给世界上每一个字符分配一个唯一编号。

这个编号叫**码点（code point）**，写成 `U+` 加十六进制，比如 `U+0041` 是字母 `A`。码点范围从 `U+0000` 到 `U+10FFFF`，容纳一百多万个字符；其中 0 到 127 这一段和 ASCII 完全重合，这是为了向前兼容。

码点只是编号，具体存成哪几个字节，是另一回事，这叫**编码方式（encoding）**。Unicode 标准委员会定了三种：

| 编码 | 表示一个码点用几个字节 | 特点 |
| --- | --- | --- |
| UTF-8 | 1 到 4 个 | 变长；ASCII 字符仍占 1 字节，与 ASCII 完全兼容 |
| UTF-16 | 基本平面 2 个，其余 4 个 | 以定长为主；Windows 内部和 Java 的 `char` 用它 |
| UTF-32 | 固定 4 个 | 定长，最好处理，也最占空间 |

**UTF-8 是今天的事实标准**，Linux、macOS、网页、绝大多数源码文件都用它。它最大的好处是变长且对 ASCII 友好：英文字符仍占 1 个字节，一个纯英文文件用 UTF-8 存和用 ASCII 存出来一模一样；汉字这类字符则要 3 个字节。

"ASCII 只占 1 字节"和"汉字要 3 字节"这个差别，是 C++ 里所有字符串编码问题的源头。

C 和 C++ 提供了两个宏描述环境的编码宽度，都来自 C 标准库：

- `MB_LEN_MAX`：实现支持的任何编码中，单个字符最多的字节数，定义在 `<climits>`。
- `MB_CUR_MAX`：当前本地化环境下单个字符最多的字节数，不超过 `MB_LEN_MAX`，定义在 `<cstdlib>`。

竞赛里它们被 `bits/stdc++.h` 一并包含，通常不用手写这两个头文件。

## 字符的表示方法

字符表示法的本质，是把字符对应到一个整数，再按编码表查这个整数是哪个字符。C++ 提供了几种在源码里直接写"整数编号"的方式：

- `\123`：八进制，反斜杠后跟三位数字。
- `\x4D`：十六进制，`\x` 后跟十六进制数。
- `\u2620`：Unicode 码点，`\u` 后跟 4 位十六进制。
- `\U0001243F`：Unicode 码点，`\U` 后跟 8 位十六进制。

```cpp
cout << "ABC\n";            // 直接写字符
cout << "\101\102\103\n";   // 八进制转义
cout << "\x41\x42\x43\n";   // 十六进制转义
```

三行都输出 `ABC`：`\101` 和 `\x41` 都等于十进制的 65，也就是 `A` 的 ASCII 码。

```cpp
cout << "\u2022 Bullet 1\n";
cout << "\U00002022 Bullet 1\n";
```

两行都输出 `• Bullet 1`。`U+2022` 是项目符号，UTF-8 下编码成 3 个字节 `E2 80 A2`：源码里是一个转义序列，编译进字符串后就是 3 个字节。

## 多字节字符的表示

在源码里写字符字面量有个前提：这个字符得是**基本字符**，也就是所有可打印的 ASCII 字符（`@`、`$`、`` ` `` 三个字符除外）。按这个规矩，非英语字符都该写成码点形式：

```cpp
const char* s = "\u6625\u5929";   // 春天
cout << s << '\n';
```

`U+6625` 是"春"，`U+5929` 是"天"。

不过现在的源码文件基本都存成 UTF-8，编译器也默认按 UTF-8 读源码，所以可以直接把中文写进字面量：

```cpp
const char* s = "春天";
cout << s << '\n';
```

结果一样。需要向编译器强调"这个字面量按 UTF-8 编码"时，可以加 `u8` 前缀：

```cpp
const char* s = u8"春天";
```

C++20 起 `u8""` 的类型变成了 `char8_t[]`，和 `char` 不再通用，写法上要留意版本差异。

`\u` 和 `\U` 这两种写法不能用来表示码点小于 `0xA0` 的字符，只有 `$`、`@`、`` ` `` 例外：

```cpp
const char* s = "\u0024\u0040\u0060";   // $@`
cout << s << '\n';
```

C++ 里 `\u` 属于"通用字符名"（universal character name），作用是在编译的识别阶段代表某个字符，最终按源码的执行字符集写进字符串。在 UTF-8 环境下，`"\u6625"` 得到的仍是 3 个字节的 UTF-8 序列，和直接写"春"没有区别。

### 字节数不等于字符数

字符串里一旦有多个字节的字符，"长度"就有两种含义——字节数和字符数，两者不再相等。`strlen()`（来自 `<cstring>`）统计的是**字节数**：

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    const char* s = "春天";
    cout << strlen(s) << '\n';   // 6
    return 0;
}
```

`s` 明明只有两个汉字，`strlen` 却返回 6，因为 UTF-8 下每个汉字占 3 个字节。`string` 的 `size()`、`length()` 同样是字节数，一个都躲不掉。

`sizeof` 在这个问题上更容易骗人。`sizeof(char)` 恒等于 1，`sizeof` 也永远数字节：

```cpp
char s[] = "春天";
cout << sizeof(s) << '\n';        // 7：6 个字节 + 结尾的 '\0'
cout << sizeof("春天") << '\n';   // 7，同上

const char* p = "春天";
cout << sizeof(p) << '\n';        // 8（64 位机器上），这是指针的大小，不是字符串长度
```

最后一行是个经典陷阱：`sizeof` 对数组名算的是整个数组的字节数，对指针算的是指针本身的字节数。想拿字符串长度，用 `strlen` 或者 `string::size()`，别用 `sizeof`。

C 的一批字符串函数是按字节工作的，碰上多字节字符就会给出错误结果：`strchr()`、`strtok()`、`strspn()`、`toupper()`、`tolower()`、`isalpha()` 都是如此。拿 `toupper()` 举例，它的合法输入只有 `unsigned char` 范围内的值；汉字那些字节根本不在合法输入里，传进去的结果是未定义的。

那么竞赛里遇到中文怎么办？实际经验是三条：

- **输入里的中文，按字节处理就行。** 把一整行读进 `string`，需要判断或修改时按字节位置操作。UTF-8 保证了每个非 ASCII 字节的最高位都是 `1`，汉字的所有字节不会和其他字符的字节混在一起，所以逐个字节扫过去不会切坏别的字符。
- **别用"第几个字符"的直觉去取下标。** 想取第 2 个汉字，`s[1]` 拿到的是第 2 个**字节**，不是第 2 个字。正确的做法是按 UTF-8 的起始字节往后跳：最高位是 `0` 的是单字节的 ASCII，`110` 开头的是 2 字节字符的首字节，`1110` 开头的是 3 字节字符的首字节，以此类推。
- **真要数字符，就先按 UTF-8 解码出码点，再数码点的个数。**

如果程序需要在运行时按本地语言解释字节，可以先用 `setlocale()` 切换本地化环境：

```cpp
setlocale(LC_ALL, "");   // 切到系统当前的本地化设置
```

也可以指定具体环境：

```cpp
setlocale(LC_ALL, "zh_CN.UTF-8");   // 中文 UTF-8
```

`setlocale()` 来自 `<clocale>`（C 的 `<locale.h>`）。竞赛里基本不需要它——评测机的输入输出通常就是 UTF-8 字节流，按字节读进来最省事，也不会因为评测机没装对应的 locale 而失败。

## 宽字符

多字节字符串有个根本麻烦：每个字符占几个字节不确定，想访问第 n 个字符就得从头一个个数。为此 C 提供了另一种方案——**宽字符（wide character）**：每个字符占固定的字节数，要么 2 个要么 4 个，按下标访问就是常数时间。

宽字符的类型是 `wchar_t`。它实际上是整数类型的别名，可能是有符号的，也可能是无符号的，由实现决定，不要依赖；长度是 16 位或 32 位，足以放下当前系统的任意字符。它定义在 `<cwchar>`（C 的 `<wchar.h>`）。

宽字符的字面量必须加前缀 `L`，否则会被当成窄字符处理：

```cpp
wchar_t c = L'牛';
```

`L` 加在单引号前是宽字符，加在双引号前是宽字符串。宽字符串的结尾也有空字符，只不过是一个或多个字节的宽空字符。

```cpp
const wchar_t* s = L"春天";
```

C 里输出宽字符要写 `%lc`、`%ls`，`cout` 那边则要靠 `wostream` 的重载，实践中最省事的还是用 `printf`：

```cpp
setlocale(LC_ALL, "");

wchar_t c = L'牛';
printf("%lc\n", c);       // 牛

const wchar_t* s = L"春天";
printf("%ls\n", s);       // 春天
```

`wchar_t` 不好用的地方在于它的宽度是平台相关的：Windows 上 `wchar_t` 是 2 字节、按 UTF-16 存，Linux 和 macOS 上是 4 字节、按 UTF-32 存，同一份代码换个平台就可能出问题。C++11 为此补了两个宽度明确的类型：`char16_t` 对应 UTF-16，`char32_t` 对应 UTF-32，字面量分别是 `u"..."` 和 `U"..."`。C++20 又加了 `char8_t` 对应 UTF-8，也就是前面提过的 `u8"..."`。

这些类型竞赛里都用不上。算法题的输入输出以 ASCII 为主；真需要处理中文，按上一节的思路当成"一串字节"来对待最省心。

处理宽字符要用宽字符专用的函数，绝大部分都在 `<cwchar>` 里。

## 多字节字符处理函数

C 标准库提供了一组函数，在多字节表示和宽字符表示之间互相转换，原型都在 `<cstdlib>`。它们依赖当前的本地化环境，用之前一般先调一次 `setlocale()`。

这些函数在竞赛里几乎不会出现，这里作为编码知识补齐：**知道"编码之间可以互换"这件事**，具体参数需要时再查文档。

### mblen()

`mblen()` 返回一个多字节字符占用的字节数。

```cpp
int mblen(const char* mbstr, size_t n);
```

第一个参数是多字节字符串指针，函数只看它的第一个字符；第二个参数是允许检查的字节数上限，一般传 `MB_CUR_MAX`。

返回值是该字符占用的字节数。如果指向的是空字符（`\0`），返回 `0`；如果这个字节序列不是合法的多字节字符，返回 `-1`。

```cpp
setlocale(LC_ALL, "");

const char* mbs1 = "春天";
cout << mblen(mbs1, MB_CUR_MAX) << '\n';   // 3

const char* mbs2 = "abc";
cout << mblen(mbs2, MB_CUR_MAX) << '\n';   // 1
```

"春"占 3 个字节，"a"占 1 个字节，正是上一节说的 UTF-8 变长表现。想求出整个字符串的字符数，就得靠这个函数一个个往前挪着数。

### wctomb()

`wctomb()`（wide character to multibyte）把单个宽字符转成多字节表示。

```cpp
int wctomb(char* s, wchar_t wc);
```

第一个参数是存放结果的多字节数组，第二个参数是要转换的宽字符。返回值是转换后占用的字节数；无法转换时返回 `-1`。如果第一个参数是空指针，它只回答"当前环境下一个宽字符最多需要多少字节"，不做转换。

```cpp
setlocale(LC_ALL, "");

wchar_t wc = L'牛';
char mbStr[10] = "";

int nBytes = wctomb(mbStr, wc);

cout << mbStr << '\n';    // 牛
cout << nBytes << '\n';   // 3
```

### mbtowc()

`mbtowc()` 反过来，把多字节字符转成宽字符。

```cpp
int mbtowc(wchar_t* wchar, const char* mbchar, size_t count);
```

三个参数分别是目标宽字符指针、待转换的多字节字符指针、允许读取的最大字节数。返回值是消耗掉的多字节字节数，转换失败返回 `-1`。

```cpp
setlocale(LC_ALL, "");

const char* mbchar = "牛";
wchar_t wc;

int nBytes = mbtowc(&wc, mbchar, 3);

cout << nBytes << '\n';    // 3
printf("%lc\n", wc);       // 牛
```

### wcstombs()

`wcstombs()` 把宽字符串整个转成多字节字符串。

```cpp
size_t wcstombs(char* mbstr, const wchar_t* wcstr, size_t count);
```

三个参数是目标多字节缓冲区、待转换的宽字符串、以及缓冲区能容纳的最大字节数。转换成功返回写入的字节数（**不含**结尾的 `\0`），失败返回 `-1`。第一个参数是空指针时，它只返回转换所需的字节数，可以用来预估缓冲区要开多大。

```cpp
setlocale(LC_ALL, "");

char mbs[20];
const wchar_t* wcs = L"春天";

size_t nBytes = wcstombs(mbs, wcs, 20);

cout << mbs << '\n';       // 春天
cout << nBytes << '\n';    // 6
```

两个汉字转成 UTF-8 是 6 个字节，和 `strlen("春天")` 的结果一致。

### mbstowcs()

`mbstowcs()` 反过来，把多字节字符串转成宽字符串。

```cpp
size_t mbstowcs(wchar_t* wcstr, const char* mbstr, size_t count);
```

三个参数是目标宽字符串、待转换的多字节字符串、以及最多转换多少个字符。转换成功返回转换出的字符数，失败返回 `-1`。如果返回值正好等于 `count`，说明目标宽字符串没用空字符收尾，是被写满截断的。

```cpp
setlocale(LC_ALL, "");

const char* mbs = "天气不错";
wchar_t wcs[20];

size_t nChars = mbstowcs(wcs, mbs, 20);

printf("%ls\n", wcs);      // 天气不错
cout << nChars << '\n';    // 4
```

"天气不错"有 4 个字符，所以返回 4——这里数的是**字符**，不是字节，和 `strlen` 数出来的 12 不是一回事。整组 API 里，只有这一对函数能帮你数对字符数。但它们依赖本地化环境，还得额外拷贝一份内存，竞赛里依旧不如按字节处理来得快。

第一个参数为空指针时，`mbstowcs()` 返回目标宽字符串会包含的字符数。
