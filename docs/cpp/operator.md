# 运算符

C++ 的运算符（operator）有 50 多个，按用途分成若干类。本章按类别逐个讲，最后给一张优先级表。

C++ 支持运算符重载（operator overloading）：同一个符号在运算数类型不同时含义可能不同。典型的例子是 `<<`，它既是移位运算符，也是输出流的插入运算符，区分方法见后文。判断表达式语义的依据是优先级、结合性和运算数类型。

## 算术运算符

算术运算符负责常规的加减乘除。下面列出常用的几个，其中 `+`、`-` 有一元和二元两种身份。

- `+`：正值运算符（一元）、加法运算符（二元）
- `-`：负值运算符（一元）、减法运算符（二元）
- `*`：乘法运算符
- `/`：除法运算符
- `%`：取余运算符，也叫求模（modulo）

**（1）`+` 和 `-`**

一元运算符只需要一个运算数，一元 `-` 用来改变值的正负号：

```cpp
int x = -12;   // -12
```

一元 `+` 不改变正负，写了等于没写，可以直接省略：

```cpp
int x = -12;
int y = +x;    // y 还是 -12
```

二元的 `+`、`-` 就是熟悉的加减法：

```cpp
int x = 4 + 22;    // 26
int y = 61 - 23;   // 38
```

**（2）`*`**

`*` 是乘法。它在 C++ 里还兼作指针的“解引用”符号，到底是乘还是解引用，看它左边有没有运算数。

```cpp
int num = 5;
cout << num * num << '\n';   // 25
```

**（3）`/`**

`/` 表示除法。两个整数相除时结果仍为整数，小数部分被丢弃，这称为整除（integer division）。

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    double x = 6 / 4;
    cout << x << '\n';   // 1，不是 1.5
    return 0;
}
```

`6 / 4` 先按整除算出 `1`，之后才转成 `double` 存进 `x`，所以 `x` 是 `1.0`。要使除法按浮点数运算，至少需要一个运算数为浮点类型：

```cpp
double x = 6.0 / 4;   // 1.5
double y = 6 / 4.0;   // 1.5，效果一样
```

将整数除法转为浮点除法的常见写法是给分子乘 `1.0`：`1.0 * sum / n`。写成 `(double)sum / n` 等价。

这是竞赛中常见的错误来源之一。计算平均值、比例、斜率时若写成 `sum / n`，两个运算数均为 `int`，小数部分被丢弃，输出结果错误且编译器不会给出提示。

以下代码属于同一类问题：

```cpp
int score = 5;
score = (score / 20) * 100;   // score 变成 0，不是 25
```

`score / 20` 是整除，得 `0`，乘以 `100` 还是 `0`。把除数改成 `20.0`，或者先乘再除、写 `score * 100 / 20`，结果才对。

**（4）取余运算与负数的规则**

`%` 返回两个整数相除的余数，只能用于整数。C++ 规定整数除法的商**向零取整**（truncate toward zero），而余数的符号跟随**被除数**（也就是左运算数），并且永远满足这条恒等式：

```cpp
a == (a / b) * b + a % b
```

以下列出几组结果：

```cpp
cout << 6 % 4 << '\n';      // 2
cout << -6 / 4 << '\n';     // -1，向零取整，不是 -2
cout << 11 % 5 << '\n';     // 1
cout << -11 % 5 << '\n';    // -1
cout << 11 % -5 << '\n';    // 1
cout << -11 % -5 << '\n';   // -1
```

C++ 中 `-11 % 5` 的结果为 `-1`，而非数学上的 `4`。将其转换到 `[0, mod)` 区间（计算下标、哈希时常用）的写法是：

```cpp
int r = (x % mod + mod) % mod;   // 结果一定非负
```

`%` 不能用于浮点数。真要对浮点取余，用 `<cmath>` 里的 `fmod`，竞赛里基本用不到。

**（5）赋值与算术的结合形式**

变量对自身做算术时，可以写成复合赋值：

- `+=`、`-=`、`*=`、`/=`、`%=`，以及后面要讲的位运算版本 `&=`、`|=`、`^=`、`<<=`、`>>=`。

```cpp
i += 3;   // 等同于 i = i + 3
i -= 8;   // 等同于 i = i - 8
i *= 9;   // 等同于 i = i * 9
i /= 2;   // 等同于 i = i / 2
i %= 5;   // 等同于 i = i % 5
```

除书写较短外，复合赋值使左侧的 `i` 只求值一次，也能避免重复书写变量名时写错。

## 自增运算符、自减运算符

`++` 让变量自身加 1，`--` 减 1：

```cpp
i++;   // 等同于 i = i + 1
i--;   // 等同于 i = i - 1
```

运算符写在变量前面还是后面，返回值不一样：

- 前置形式 `++i`：先加 1，再返回加完之后的值；
- 后置形式 `i++`：先返回加之前的值，再加 1。

```cpp
int i = 42, j;

j = i++ + 10;   // 先用 42 参与运算，之后 i 变 43：j = 52，i = 43
j = ++i + 10;   // i 先变 44，再参与运算：j = 54，i = 44
```

同一个表达式中既读取又修改同一个变量时，`i++ + ++i` 这类写法属于未定义行为（undefined behavior），编译器给出任何结果都符合标准。应将自增操作单独写成一条语句：

```cpp
/* 写法一 */
j = i + 10;
i++;

/* 写法二 */
i++;
j = i + 10;
```

这样 `i` 的修改位置明确，也不涉及未定义行为。

迭代器的自增同样有前置与后置两种形式。后置版本需要先复制旧迭代器再返回，因此对于结构复杂的迭代器，使用 `++it` 可省去一次拷贝开销；对 `int` 这类基本类型两者没有差别。竞赛代码中遍历容器通常写作 `++it`。

## 关系运算符

关系表达式用于比较，运算符有 6 个：

- `>` 大于
- `<` 小于
- `>=` 大于等于
- `<=` 小于等于
- `==` 等于
- `!=` 不等于

```cpp
a == b;
a != b;
a < b;
a > b;
a <= b;
a >= b;
```

这些表达式的值是布尔型 `bool`，结果要么是 `true`，要么是 `false`，用 `cout` 输出出来就是 `1` 和 `0`：`20 > 12` 得 `1`，`12 > 20` 得 `0`。关系表达式最常出现在 `if`、`while` 的条件位置。

想直接打印比较结果时，括号别省：

```cpp
int a = 3, b = 5;
cout << (a < b) << '\n';   // 1
```

不加括号写成 `cout << a < b`，编译器会先结合 `<<`（它的优先级高于 `<`），语义变为先输出 `a`，再将 `cout` 与 `b` 比较，无法通过编译。

**相等判断使用 `==`，赋值使用 `=`。** 赋值表达式本身也有值（等于右侧的值），所以下面这两行能编译、能运行，但行为不等于相等判断：

```cpp
if (x = 3)             // 本意是 x == 3
    cout << "yes\n";
```

赋值 `x = 3` 的值为 `3`，非零即真，该判断恒成立。将常量写在左侧可避免这一问题：写成 `if (3 == x)` 时，误写为 `3 = x` 会直接编译报错。编译器通常也会对 `if (x = 3)` 给出警告，编译时加上 `-Wall` 可输出这类警告。

**关系运算符不能连用。** `i < j < k` 是合法表达式，但它不表示“`j` 在 `i` 和 `k` 之间”。`<` 从左到右结合，实际算的是 `(i < j) < k`：先得到 `0` 或 `1`，再拿这个 `0`/`1` 和 `k` 比较。要表达区间就用逻辑与：

```cpp
if (i < j && j < k) ...
```

## 逻辑运算符

逻辑运算符有三个：

- `!`：逻辑非，把单个表达式的真假取反；
- `&&`：逻辑与，两侧都为真时才为真；
- `||`：逻辑或，两侧有一个为真就为真。

```cpp
if (x < 10 && y > 20)
    cout << "Doing something\n";
```

任何非零值都表示真，零表示假。`5 || 0` 得 `1`，`5 && 0` 得 `0`。

`!` 的优先级比关系运算符高，要对整个比较式取反，必须加括号：

```cpp
if (!(x < 12)) ...   // 等价于 if (x >= 12)，实际写后者更清楚
```

**短路求值（short-circuit）** 指 `&&` 和 `||` 先求值左侧运算数，若左侧结果已能确定整个表达式的值，右侧不再求值。竞赛中常利用这一性质将越界检查放在左侧：

```cpp
// 先判 i - 1 >= 0，右边才不会访问 v[-1]
if (i - 1 >= 0 && v[i - 1] == target) ...
```

`&&` 左侧不成立时，右侧的 `v[i - 1]` 不会被求值，因此不会发生越界访问。若将 `v[i - 1]` 写在左侧，则失去这一保护。

短路求值也带来副作用方面的问题：

```cpp
while (x++ < 10 && x + y < 20)   // 别这么写
```

左侧求值后 `x` 已自增，右侧的 `x + y` 使用自增后的值，与预期的写法通常不一致。带有自增的表达式不放在逻辑运算符两侧。

## 位运算符

位运算符直接处理二进制位（bit），共 6 个，另外 `~` 是一元运算符。

**（1）取反 `~`**

把每一位取反：`0` 变 `1`，`1` 变 `0`。它不改变原变量，只返回一个新值。

```cpp
// 01101100
~10010011
```

**（2）按位与 `&`**

两位都为 `1` 才得 `1`：

```cpp
// 00010001
10010011 & 00111101
```

**（3）按位或 `|`**

有一位为 `1` 就得 `1`：

```cpp
// 10111111
10010011 | 00111101
```

**（4）按位异或 `^`**

两位不相同时得 `1`，相同时得 `0`：

```cpp
// 10101110
10010011 ^ 00111101
```

异或有两个常用性质：`x ^ x == 0`，`x ^ 0 == x`。在一堆数里找唯一出现奇数次的数，全部异或起来剩下的就是它。

**（5）左移 `<<`**

每一位向左移动，右边空出的位补 `0`：

```cpp
// 1000101000
10001010 << 2
```

左移 `k` 位相当于乘以 2 的 `k` 次方。有符号整数左移溢出符号位时属于未定义行为；C++20 起明确为按 2 的幂环绕，按 C++17 编译时结果不确定。

**（6）右移 `>>`**

每一位向右移动，低位多出来的直接丢弃：

```cpp
// 00100010
10001010 >> 2
```

右移 `k` 位相当于除以 2 的 `k` 次方（对非负数等价于整除）。**右移负数**的补位规则在 C++20 之前由实现决定，C++20 起规定为算术右移（高位补符号位）。要使右移等价于除以 2 的幂，操作数应使用非负整数。

这六个运算符都能和赋值结合，写成 `&=`、`|=`、`^=`、`<<=`、`>>=`：

```cpp
val &= 0377;   // val = val & 0377，0377 是八进制写法
val |= 0377;
val ^= 0377;
val <<= 2;
val >>= 2;
```

### 位运算在竞赛里的用途

位运算的实际用途之一是用一个整数表示一组二元状态，替代若干个布尔变量或数组。以下是竞赛中常见的几类用法。

**（1）取出和修改某一位。** 常用写法如下：

```cpp
int x = 0b10110;

x >> k & 1;          // 取出第 k 位（结果是 0 或 1）
x |= 1 << k;         // 把第 k 位置 1
x &= ~(1 << k);      // 把第 k 位清 0
x ^= 1 << k;         // 把第 k 位翻转
x & -x;              // 最低位的 1（lowbit），树状数组的基础操作
```

顺带一个常用判断：`x & (x - 1)` 会把最低位的 1 抹掉，所以 `x && !(x & (x - 1))` 可以用来判断 `x` 是不是 2 的幂。

**（2）子集枚举。** 用一个二进制位表示某个元素“选还是不选”，一个整数就能装下 32 个元素的子集；枚举所有子集，就是依次枚举所有掩码：

```cpp
int n = 5;
for (int s = 0; s < (1 << n); s++) {
    for (int i = 0; i < n; i++) {
        if (s >> i & 1) {
            // 当前子集包含第 i 个元素
        }
    }
}
```

复杂度为 O(2^n · n)，`n` 超过 20 后需要改用其他方法。此外，`1 << n` 中的 `1` 是 `int`，`n` 达到 31 时 `1 << 31` 溢出（未定义行为），应写成 `1LL << n`，并将 `s` 声明为 `long long`。

**（3）状态压缩。** 动态规划里如果状态是“哪些元素已经选了”，就把这个集合编码成一个整数，直接当 `dp` 数组的下标——这叫状态压缩（bitmask DP）。比如在 `n <= 20` 的点集上找哈密顿路径，`dp[mask][v]` 表示“已访问点集为 `mask`、当前停在 `v`”的最优值。位运算在这里负责：判断某点是否已访问用 `mask >> u & 1`，把点加入集合用 `mask | 1 << u`。

**（4）取模的写法。** `%` 的开销高于位运算，模数为 2 的幂时，`x % (1 << k)` 可写成 `x & ((1 << k) - 1)`；哈希表、环形缓冲区将容量设为 2 的幂即为此目的。求两数乘积的模时应先转为 `long long`，写成 `1LL * a * b % mod`，否则中间结果可能先溢出 `int`。

**（5）`__builtin` 系列。** GCC 还提供了一批位运算内在函数，竞赛里常被用到的是 `__builtin_popcount(x)`（数二进制里 1 的个数）和 `__builtin_clz(x)`（数前导零的个数），比自己写循环快。它们不属于标准 C++，但在竞赛用的 GCC/Clang 上都能用。

### 关于 `<<` 和 `>>` 的两副面孔

同一个符号在两种场合含义不同，这是 C++ 初学者容易混淆的地方之一：

```cpp
int a = 1 << 3;              // 移位：a = 8
cout << a << '\n';           // 输出：流插入
```

区分靠左边运算数的类型：`cout`、`cin` 是流对象，`<<`、`>>` 走的是重载后的“插入 / 提取”版本；两边都是整数时，走的是内置的移位版本。二者的优先级相同，都是从左到右结合，所以 `cout << a << b` 会被理解成 `((cout << a) << b)`——正好就是“先输出 a，再输出 b”的意思。同理 `cin >> a >> b` 等价于 `(cin >> a) >> b`。

这也解释了前面那条建议：想输出比较结果，得写 `cout << (a < b)`。因为 `<<` 的优先级高于 `<`，不写括号就变成 `(cout << a) < b` 了。

### 一个必须小心的优先级问题

位运算符的优先级**低于**关系运算符，所以下面这行是错的：

```cpp
if (x & 1 == 0) ...   // 实际是 x & (1 == 0)，也就是 x & 0，永远为假
```

`==` 先结合，`1 == 0` 得 `0`，整个式子恒为 `0`，判断永远不成立，编译器也不会给出警告。正确写法是加括号：

```cpp
if ((x & 1) == 0) ...
```

此外，`&`、`|` 是按位运算符，**没有短路性质**，两侧运算数都会被求值，不能当作 `&&`、`||` 使用；`a & b` 中的 `b` 一定会被求值，前文那种用左侧运算防止越界的写法在 `&` 上不成立。

## 逗号运算符

逗号 `,` 在 C++ 中有两种角色。声明语句里的逗号只是分隔符（`int a, b;`），而作为运算符时，它把多个表达式串起来，从左到右依次求值，整个逗号表达式的值等于**最后一个**表达式的值。

```cpp
x = 10, y = 20;   // 先算 x = 10，再算 y = 20
```

```cpp
int x;
x = (1, 2, 3);    // x 等于 3
```

`for` 的条件部分是逗号运算符最常出现的地方：

```cpp
for (int i = 0, j = 999; i < 10; i++, j--)
    cout << i << ' ' << j << '\n';
```

逗号运算符的优先级在所有运算符中最低，`x = 1, 2` 与 `x = (1, 2)` 含义不同：前者将 `1` 赋给 `x`，随后求值 `2` 并丢弃结果；后者 `x` 的值为 `2`。除 `for` 的多步更新外，竞赛代码中不使用逗号运算符：它的可读性较差，也不带来功能上的收益。

## 运算优先级

一个表达式里出现多个运算符时，谁先算由**优先级（precedence）**决定：

```cpp
3 + 4 * 5;   // 先算 4 * 5，再算 3 + 20，得 23
```

优先级相同的运算符，则按**结合性（associativity）**决定执行顺序。绝大多数运算符从左到右（左结合），赋值运算符和三元运算符是从右到左（右结合）：

```cpp
5 * 6 / 2;    // 左结合：先 5 * 6 = 30，再 30 / 2 = 15
a = b = c;    // 右结合：先算 b = c，再把结果赋给 a
```

下表列出本章涉及的运算符，从上到下优先级由高到低：

| 优先级 | 运算符 | 结合方向 |
| --- | --- | --- |
| 1（最高） | `()`、`[]`、`->`、`.` | 左 |
| 2 | `++`、`--`（后置）、`!`、`~`、一元 `+` `-`、`*`（解引用）、`&`（取地址）、`sizeof` | 右 |
| 3 | `*`、`/`、`%` | 左 |
| 4 | `+`、`-` | 左 |
| 5 | `<<`、`>>` | 左 |
| 6 | `<`、`<=`、`>`、`>=` | 左 |
| 7 | `==`、`!=` | 左 |
| 8 | `&`（按位与） | 左 |
| 9 | `^` | 左 |
| 10 | 按位或 | 左 |
| 11 | `&&` | 左 |
| 12 | 逻辑或 | 左 |
| 13 | `?:` | 右 |
| 14 | `=` 及各种复合赋值（`+=`、`-=`、`&=`、`<<=` 等） | 右 |
| 15（最低） | `,` | 左 |

对照上表，以下优先级关系容易出错：`<<`、`>>` 的优先级高于关系运算符，而 `==` 又高于按位与。下面这句会先算移位：

```cpp
if (a & 1 << 2) ...   // 实际是 a & (1 << 2)
```

这张表不需要逐条记忆。**拿不准就加括号**：括号优先级最高，既锁定语义，也免去阅读时对优先级的推断。前面出现的 `cout << (a < b)`、`(x & 1) == 0`，都是这一写法的实例。
