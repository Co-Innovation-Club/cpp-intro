# 变量说明符

声明变量时，可以在类型前后加上一些关键字，为编译器提供额外的信息——这个值能不能改、变量存在哪个存储区、生成代码时能不能做某项优化。这类关键字叫**说明符（specifier）**。多数说明符只是给编译器的“提示”，不影响程序的语义；少数会实打实地改变变量行为，写错了就是编译错误。

按竞赛里的出现频率排，`const` 和 `static` 是常客，`auto` 有和 C 完全不同的新含义，`extern` 在多文件工程里露面，剩下的 `register`、`volatile`、`restrict` 属于底层开发的知识，竞赛题里基本碰不到，但读别人的代码时要知道它们在说什么。

## const

`const` 表示变量只读，不能修改。试图赋值，编译器当场报错：

```cpp
const double PI = 3.14159;
PI = 3;   // 报错：PI 是只读的
```

数组加了 `const`，成员也不能改：

```cpp
const int arr[] = {1, 2, 3, 4};
arr[0] = 5;   // 报错
```

### 竞赛里用它定义常量

题目里的数组上限、模数、无穷大，惯例用 `const` 写：

```cpp
const int MAXN = 100005;
const int MOD = 1000000007;
const long long INF = 0x3f3f3f3f3f3f3f3fLL;
```

它比 `#define` 好在哪儿？`#define MAXN 100005` 是纯粹的文本替换：没有类型，没有作用域，调试器里看不见，出了问题也不会给你类型检查。`const int MAXN = 100005;` 是一个货真价实的 `int` 常量，参与类型检查，名字在调试信息里也在，报错会指到正确的位置。

需要**编译期**就能算出来的场合——数组长度、`case` 标签、模板参数——用 `constexpr` 更明确：

```cpp
constexpr int MAXN = 100005;
int a[MAXN];   // 合法：MAXN 是编译期常量
```

`constexpr` 是 C++11 引入的，含义是“这个值在编译期确定”。普通 `const` 变量如果由常量表达式初始化，其实也能满足编译期要求，只是语义上没有 `constexpr` 直白。日常写常量，`const` 够用；需要强制编译期求值时换 `constexpr`。至于 `#define`，就把它留给条件编译开关这类预处理用途吧（见《预处理器》一章）。

### 指针与 const

`const` 修饰指针时，位置不同含义完全不同：

```cpp
const int* x;   // 同 int const* x：*x 不能改，x 本身可以改
int* const x;   // x 保存的地址不能改，*x 可以改
```

`const` 在 `*` 左边，管的是指针指向的内容：

```cpp
int p = 1;
const int* x = &p;
(*x)++;   // 报错：不能通过 x 修改 p
x++;      // 合法：x 自己换了个地址
```

`const` 在 `*` 右边，管的是指针自己：

```cpp
int p = 1;
int* const x = &p;
x++;      // 报错：x 的地址不可改
(*x)++;   // 合法：p 变成 2
```

两种写法可以叠在一起。`const char* const x` 意味着 `x` 的地址和它指向的字符串都不能动。

有一条读法上的小窍门：从变量名开始，先往右读，再往左读。`const int* x` 读成“`x` 是指针，指向 `const int`”；`int* const x` 读成“`x` 是常量，类型是 `int*`”。

### 函数参数里的 const

给参数加 `const`，是明明白白告诉调用者“这东西在函数里不会被改”，同时也让编译器拦下手滑的修改：

```cpp
void find(const int* arr, int n);
```

C++ 里传大对象（`vector`、`string`）时，惯例是用 **const 引用**，既避免拷贝又保证只读：

```cpp
void printAll(const vector<int>& v);
```

这一行把两件事写清楚了：`&` 表示不拷贝，`const` 表示不改。竞赛里函数参数写成 `const vector<int>&` 是标配，写成 `vector<int>` 会平白多拷一份，数据一大就超时。

还有一种情况要注意：指针指向 `const` 变量时，通过它改值同样不合法，即使指针自己没写 `const`。

```cpp
const int i = 1;
int* j = &i;   // 报错：不能把 const int* 赋给 int*
```

编译器在这一行就拦住了。C++ 的类型检查比 C 严，这种“偷偷丢掉 const”的赋值基本逃不掉。

## static

`static` 的三种用法含义各不相同，得分开看。

**（1）函数内部的局部变量。** 值在函数返回后保留，下次进函数还能接着用；初始化只做一次。

```cpp
void f() {
    static int cnt = 0;   // 只在第一次进入 f 时执行这次初始化
    cnt++;
    cout << cnt << '\n';
}
```

连着调三次 `f()`，输出 `1`、`2`、`3`。这个变量的生命周期是整个程序，作用域却只在 `f` 里面，像一个“只有这个函数看得见的全局变量”。

竞赛里这一点常被当成陷阱：如果多组测试数据共用同一个函数，`static` 变量不会在每组数据开始时归零，忘了手动清零就会一直往上累加。所以除非是刻意做记忆化，竞赛代码很少在函数里写 `static`。

**（2）全局变量。** 在文件最外层加 `static`，表示这个变量只归当前文件用，别的源文件引用不到。它改的是变量的**链接属性（linkage）**，也就是链接器能不能在别的文件里找到这个名字。

顺带说一件与 C 不同的地方：C 要求静态存储期的变量必须用常量表达式初始化，C++ 放宽了这条限制，全局/静态变量可以用运行时算出来的值初始化：

```cpp
int n = 10;
static int m = n;   // C++ 合法；同样写法在 C 里是错误
```

C++ 允许，但这类初始化要到 `main()` 之前才执行（叫动态初始化），多个这样的全局变量之间谁先谁后是不确定的，程序里不要依赖它们的相互顺序。函数内部 `static` 变量的动态初始化则发生在第一次执行到声明处时，C++11 起这一步是线程安全的。

**（3）函数。** 只在本文件使用的函数可以声明为 `static`，这样别的文件也能定义同名函数而不冲突：

```cpp
static int g(int i);
```

单文件的竞赛代码里，“文件私有”这个作用完全无从体现——反正只有一个文件。它真正的用武之地是多文件工程，见《多文件项目》一章。

### 竞赛里“全局数组自动清零”

和 `static` 相关，还有一条竞赛里的常识必须记住：**全局变量和 `static` 变量存在静态存储区，如果没显式初始化，会被自动零初始化。** 局部变量在栈上，没这待遇，值是随机的。

所以竞赛代码经常把数组直接开到文件最外层：

```cpp
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 100005;
int a[MAXN];              // 全局数组：自动全是 0，不用手写循环清零
long long sum[MAXN];

int main() {
    cout << a[0] << ' ' << sum[MAXN - 1] << '\n';   // 0 0
    return 0;
}
```

题目有多组数据时，全局数组不会自己重新清零，得手动处理。写一个循环刷一遍，或者用 `memset`：

```cpp
memset(a, 0, sizeof(a));      // 全部置 0
memset(a, 0x3f, sizeof(a));   // 全部置 0x3f3f3f3f，常用来当"无穷大"
memset(a, -1, sizeof(a));     // 全部置 -1（每个字节都是 0xff）
```

`memset` 来自 `<cstring>`，按**字节**填充，所以只适合刷成“每个字节都相同”的值。想刷 `0x3f3f3f3f` 这种大数，每个字节都是 `0x3f`，可以；想刷成 `1` 就做不到——结果是每个字节 `0x01`，读出来是 `16843009`。写 `memset(a, 1, sizeof(a))` 是竞赛里的经典错误。

## auto

C 的 `auto` 表示“自动存储期”，可自动存储本来就是默认行为，这个关键字等于白写。到了 C++，`auto` 这个名字被保留下来，但从 C++11 起改成了完全不同的东西：**类型推导（type deduction）**，让编译器根据初始值自己推断变量类型。

```cpp
auto x = 1;      // x 是 int
auto y = 1.5;    // y 是 double
```

`auto` 必须在声明的同时给出初始值，否则编译器没有线索可推，直接报错。它推出来的类型和初始值类型一致，不会帮你做隐式提升（除非显式转换或者用引用）。

竞赛里 `auto` 主要出现在两处。一是长到不想手写的类型，尤其迭代器：

```cpp
map<string, int> mp;
for (auto it = mp.begin(); it != mp.end(); it++)
    cout << it->first << ' ' << it->second << '\n';
```

二是范围 for。

```cpp
vector<int> v = {3, 1, 4, 1, 5};

for (auto x : v)          // x 是 int，拿到的是副本
    cout << x << ' ';

for (auto& x : v)         // 引用：能改到 v 的元素，也省掉一次拷贝
    x *= 2;

for (const auto& x : v)   // 只读且不拷贝，遍历大对象的标准写法
    cout << x << ' ';
```

要留心的正是这三行的差别：`auto x` 拷一份，`auto& x` 是引用，`const auto& x` 是只读引用。遍历 `vector<pair<int,int>>` 这类元素时，写 `auto` 会平白多拷一次，写 `auto&` 才对。

C++17 还支持**结构化绑定（structured binding）**，一次把 `pair` 或结构体的成员拆开：

```cpp
pair<int, int> p = {1, 2};
auto [x, y] = p;   // x = 1，y = 2
```

## extern

`extern` 说明这个变量或函数是在别的文件里定义的，当前文件只是**声明**它，不分配存储空间。换句话说，`extern` 负责把名字告诉编译器，实体那份内存由别的文件提供。

```cpp
extern int a;   // 声明：a 在哪定义不关我的事，我只要能用它
```

这里要分清**声明（declaration）**和**定义（definition）**。`int a;` 是定义，会真的分配一块内存；`extern int a;` 是声明，只让编译器知道有这么个名字。一个变量可以声明很多次，但只能定义一次——这条规则叫单一定义原则（one definition rule, ODR），多文件项目的链接错误大多由它引起。

声明时顺手初始化，`extern` 就失效了，因为初始化意味着这里要产生实体：

```cpp
extern int i = 0;   // 等同于 int i = 0;，extern 没起作用
```

函数默认就是 `extern`，即可被其他文件调用，所以函数声明通常不写这个关键字：

```cpp
extern int f(int i);
// 等同于
int f(int i);
```

单文件竞赛代码里没有“别的文件”，`extern` 自然用不上。多文件工程用它共享全局变量，写法见《多文件项目》一章。

## register

`register` 在 C 里是给编译器的建议：这个变量用得很频繁，尽量放进 CPU 寄存器。CPU 内部的寄存器读写比内存快得多，但数量极少。编译器可以不听这个建议。

```cpp
register int a;
```

寄存器不属于内存，没有地址，所以被 `register` 修饰的变量不能取地址：

```cpp
register int a;
int* p = &a;   // 报错：a 可能不在内存里
```

这条限制现在只是历史遗迹。现代编译器自己做寄存器分配，比人手上的提示准得多；而 `register` 这个说明符在 C++11 里被弃用，**C++17 直接删掉了**——用 `-std=c++17` 编译 `register int a;`，GCC 会报 `ISO C++17 does not allow 'register' storage class specifier`。它作为关键字仍然保留，也就是仍然不能拿 `register` 当变量名。

竞赛里想让代码跑得快，正确的做法是给编译器开优化：

```bash
g++ -std=c++17 -O2 -o a a.cpp
```

`-O2` 打开常用优化，谁该进寄存器交给编译器判断。

## volatile

`volatile` 告诉编译器：这个变量的值可能在程序控制之外发生变化，每次用它都必须老老实实重新从内存里读，不许缓存，也不许把多次读写合并成一次。

```cpp
volatile int foo;
volatile int* bar;
```

它的用途集中在硬件寄存器和信号处理这类场景。硬件寄存器的值随设备状态变化，同一地址读两遍可能得到不同结果，要是编译器把第一次读的值缓存起来复用，程序就错了。信号处理函数里被异步修改的变量也属于这一类。

```cpp
int foo = x;
// ... 中间没有任何语句修改 x
int bar = x;
```

没有 `volatile` 时，编译器看到两次读 `x` 的中间没人动过它，可能只读一次、把值复用给 `foo` 和 `bar`。加上 `volatile`，它就会老老实实读两次。

关于 `volatile` 有一个流传很广的误解：它**不保证原子性，也不保证线程安全**。它只约束编译器不要跨读写做优化，对多核 CPU 的乱序执行和缓存一致性毫无办法。写多线程程序要用 `<atomic>` 里的原子类型或者互斥量，别指望 `volatile`。竞赛是单线程程序，用不到它。

## restrict

`restrict` 是 C99 引入的说明符，**C++ 标准里没有**——它属于 C 的扩展，GCC 在 C++ 里以 `__restrict__`（或 `__restrict`）的形式提供。

它的作用只有一个：告诉编译器“这块内存只通过我这一条路径访问”，于是编译器可以放手做更激进的优化。

```cpp
int* restrict pt = (int*)malloc(10 * sizeof(int));
```

上面这行声明 `pt` 是访问这块内存的唯一途径。反过来说，同一块内存能从两个地方读写，就不能加 `restrict`：

```cpp
int foo[10];
int* bar = foo;   // foo 和 bar 指向同一块内存，foo 不能声明成 restrict
```

用在函数参数上时，`restrict` 表示两个参数的地址不重叠：

```cpp
void swap(int* restrict a, int* restrict b) {
    int t = *a;
    *a = *b;
    *b = t;
}
```

编译器知道 `a`、`b` 互不干扰，就不必为“写 `*a` 会不会影响到 `*b`”插入额外的检查。要留意的是，如果传进来的两个指针实际重叠，程序行为是**未定义的**——`restrict` 是你向编译器做出的承诺，承诺错了后果自负。

竞赛里没有手写 `restrict` 的场合，把它当成理解编译器优化的背景知识就够了。
