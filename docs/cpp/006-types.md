# 数据类型

每个值都有类型（type）。编译器根据值的类型确定其取值范围、可参与的运算以及运算结果的类型。

C++ 的基本类型有三类：字符（`char`）、整数（`int`）和浮点数（`double`）。前面几章介绍的变量和表达式都以这些基本类型为基础。本章介绍每种类型的**边界**。竞赛程序中的许多错误源于数值超出其类型的取值范围。

## 字符类型

字符类型用 `char` 声明，表示单个字符。

```cpp
char c = 'B';
```

字符常量必须放在单引号里。`char` 占一个字节（8 位）。C++ 将其作为整数处理，因此 `char` 是宽度为一个字节的整数。每个字符对应一个由 ASCII 码规定的整数，例如 `B` 对应 `66`。在取值范围内，整数和字符可以互换，字符也可以参与算术运算。

```cpp
char a = 'B';          // 等同于 char a = 66;
char b = 'C';          // 等同于 char b = 67;
cout << a + b << '\n'; // 输出 133
```

上面的 `a + b` 表示两个整数相加。`char` 参与运算时会先提升为 `int`（见后面的“整数类型的运算”）。

竞赛代码经常使用字符与整数的对应关系。判断字符是否为小写字母以及将字母映射到 `0` 到 `25` 的下标，都可以直接使用减法：

```cpp
char ch = s[i];
if (ch >= 'a' && ch <= 'z')
    int idx = ch - 'a';   // 'a' 对应 0，'z' 对应 25
```

### 符号性

`char` 等同于 `signed char` 还是 `unsigned char`，**由编译器决定**，标准没有规定。多数平台上的 `char` 是有符号类型，范围为 `-128` 到 `127`；部分平台上则是无符号类型，范围为 `0` 到 `255`。两种范围都能覆盖 `0` 到 `127` 的 ASCII 字符，因此处理 ASCII 字符时没有区别。

```cpp
signed char c;   // -128 到 127
unsigned char c; // 0 到 255
```

依赖 `char` 存储大于 `127` 的值或表示负数会使代码失去可移植性。这属于实现相关（implementation-defined）行为。需要明确取值范围时，应使用 `signed char` 或 `unsigned char`。

这一规则与 `int` 不同：`int` 一定等同于 `signed int`，不由具体实现决定。

### 转义字符

单引号本身也是字符，要表示它必须用反斜杠转义。

```cpp
char t = '\'';
```

反斜杠开头的写法主要用来表示那些无法直接打印的控制字符，它们同样是字符类型的值。

- `\a`：警报，终端会响铃或闪烁。
- `\b`：退格，光标回退一格但不删除字符。
- `\f`：换页符，现代系统上行为已接近 `\v`。
- `\n`：换行符。竞赛输出通常使用该字符，理由见《基本语法》。
- `\r`：回车符，光标移回本行开头。
- `\t`：制表符，光标移到下一个制表位，通常是下一个 8 的倍数。
- `\v`：垂直分隔符，光标移到下一行的同一列。
- `\0`：空字符（null），表示没有内容，它的值为 `0`。

字符也可以写成八进制或十六进制形式。

- `\nn`：八进制写法，`nn` 是八进制值。
- `\xnn`：十六进制写法，`nn` 是十六进制值。

```cpp
char x = 'B';
char x = 66;
char x = '\102'; // 八进制
char x = '\x42'; // 十六进制
```

这四种写法完全等价，都表示整数 `66`。可直接书写的字符通常采用 `'B'` 形式，无法直接输入的字符采用转义写法。

## 整数类型

整数用 `int` 声明。这是竞赛代码中使用频率最高的类型，也是经常发生类型错误的类型。

### 简介

```cpp
int a;
```

`int` 的宽度由实现决定，常见是 4 个字节（32 位），也可能是 2 个字节或 8 个字节。**竞赛平台上的 `int` 通常按 32 位处理**，即 4 个字节：

| 宽度 | 取值范围 |
| --- | --- |
| 16 位 | -32,768 到 32,767 |
| 32 位 | -2,147,483,648 到 2,147,483,647 |
| 64 位 | -9,223,372,036,854,775,808 到 9,223,372,036,854,775,807 |

`int` 在 32 位下的上限约为 **21 亿**（2,147,483,647）。

估算乘积或总和的上界时，结果只要可能超过 21 亿，就必须使用 `long long`。例如，`n` 最大为 `10^5`、每个数最大为 `10^9` 时，求和结果的上界是 `10^14`。使用 `int` 存储该结果必然溢出；程序不会报错，但答案会错误。

### signed 与 unsigned

`signed` 表示类型带正负号；`unsigned` 表示不带符号，只能表示零和正整数。`int` 默认带符号，所以 `int` 等同于 `signed int`，`signed` 一般省略。

```cpp
signed int a;
// 等同于
int a;
```

加上 `unsigned`，同样长度的内存能表示的最大值大约翻一倍。

```cpp
unsigned int a;
```

`int` 可以省略，所以也可以写成 `unsigned a;`。

竞赛代码通常不使用 `unsigned`，原因见下文。常见的无符号类型是 `size_t`。

### 整数的子类型

`int` 使用 4 个字节存储小整数时可能占用不必要的空间，而部分场合需要超过 8 个字节的存储范围。C++ 在 `int` 之外提供了三个整数子类型，用于选择不同的取值范围。

- `short int`（简写 `short`）：宽度不多于 `int`，一般是 2 个字节，范围 -32768 到 32767。
- `long int`（简写 `long`）：宽度不少于 `int`，至少 4 个字节。
- `long long int`（简写 `long long`）：宽度多于 `long`，至少 8 个字节。

```cpp
short int a;
long int b;
long long int c;
```

`short`、`long`、`long long` 默认都带符号，也可以加 `unsigned`。`int` 都可以省略：

```cpp
short a;
unsigned short a;

long b;
unsigned long b;

long long c;
unsigned long long c;
```

竞赛代码通常按以下方式选择这三种类型：

- `long` 很少使用。它在不同平台上可能是 4 字节或 8 字节，宽度不统一；`int` 和 `long long` 可以覆盖竞赛中的常见需求。
- `short` 只在需要严格控制内存占用时使用，例如包含上百万个元素的数组。现代竞赛题很少受这部分内存限制，通常使用 `int`。
- **`long long` 是常用的整数类型**。它至少占 8 个字节，范围大约为 `-9.2 × 10^18` 到 `9.2 × 10^18`。

`long long` 可以表示 `10^18` 量级的数以及 `10^9 × 10^9` 的乘积。如果使用 `int` 计算 `n * (n + 1) / 2`，那么 `n` 最大为 `10^6` 时需要改用 `long long`，并保证中间结果也按 64 位计算：

```cpp
int n;
long long sum = 1LL * n * (n + 1) / 2;   // 先乘 1LL，把整个表达式拉到 64 位
```

`1LL *` 是竞赛代码中的常见写法，字面量后缀一节会说明它必须位于**最前面**的原因。

### 整数类型的极限值

每种类型的最大值和最小值都有对应的标准库常量。这些常量定义在标准库头文件 `<climits>` 中，该头文件专门用于提供整数类型的极限值常量，使用前需要包含它；其中的名称位于 `std` 命名空间（`<climits>` 由 C 标准库的 `<limits.h>` 演变而来）。

- `SCHAR_MIN`、`SCHAR_MAX`：`signed char` 的最小值、最大值。
- `SHRT_MIN`、`SHRT_MAX`：`short` 的最小值、最大值。
- `INT_MIN`、`INT_MAX`：`int` 的最小值、最大值。
- `LONG_MIN`、`LONG_MAX`：`long` 的最小值、最大值。
- `LLONG_MIN`、`LLONG_MAX`：`long long` 的最小值、最大值。
- `UCHAR_MAX`、`USHRT_MAX`、`UINT_MAX`、`ULONG_MAX`、`ULLONG_MAX`：各无符号类型的最大值。
- `SIZE_MAX`：`size_t` 能表示的最大值。

使用这些常量可以避免手写数值及其位数错误：

```cpp
cout << INT_MAX << '\n';    // 2147483647
cout << LLONG_MAX << '\n';  // 9223372036854775807
```

这些常量在竞赛代码中常用作“无穷大”。最短路和区间 DP 等算法需要使用大于任何合法答案的初值，可以采用以下写法：

```cpp
const int INF = 1e9;              // 10^9 + 7 这类题目里够用，还能加两次不溢出
const long long INFLL = 4e18;     // 64 位版本的"无穷大"
```

使用 `INT_MAX` 表示无穷大时，`INT_MAX + 1` 会溢出。因此，`int` 类型通常使用 `1e9`（或 `0x3f3f3f3f` ≈ 1.06 × 10^9）表示无穷大；该值与上限之间的余量可以支持两次加法。

### 整数的进制

整数默认按十进制书写。八进制用前缀 `0`，十六进制用前缀 `0x` 或 `0X`。

```cpp
int a = 012;    // 八进制，等于十进制的 10
int b = 0x1A2B; // 十六进制，等于十进制的 6699
```

`0b` 前缀表示二进制数。它从 C++14 起是标准语法，不再依赖编译器扩展。

```cpp
int x = 0b101010;   // 二进制，等于十进制的 42
```

**进制只影响书写方式，不影响存储**。所有整数在内存中都采用二进制表示。不同进制的整数可以出现在同一表达式中，`10 + 015 + 0x20` 是合法表达式。

使用 `cout` 按指定进制输出时，对应的操纵符会持续生效。后续输出需要恢复为十进制时，应重新设置相应的操纵符。

```cpp
int x = 100;
cout << hex << x << '\n';   // 64（十六进制）
cout << oct << x << '\n';   // 144（八进制）
cout << dec << x << '\n';   // 100（回到十进制）
```

如果只需按指定进制输出一次且不能影响后续输出，可以使用标准库头文件 `<cstdio>` 提供的格式化输出函数 `printf`。`printf` 的第一个参数是格式串：普通字符按原样输出，`%d`、`%o`、`%x` 这类占位符依次对应后面的实参，分别把整数按十进制、八进制、十六进制输出；占位符中的 `#` 表示输出时带进制前缀，`%X` 表示十六进制的字母与前缀都采用大写。

```cpp
int x = 100;
printf("dec = %d\n", x);    // 100
printf("octal = %o\n", x);  // 144
printf("hex = %x\n", x);    // 64
printf("octal = %#o\n", x); // 0144，带前缀
printf("hex = %#x\n", x);   // 0x64，带前缀
printf("hex = %#X\n", x);   // 0X64，前缀字母大写
```

竞赛代码中的十六进制和 `0b` 更常用于位运算的掩码，例如枚举子集和状态压缩，而不是输出。交互题或调试输出可以使用 `printf` 的 `%#x`。

## 浮点数类型

带小数点的数值会被编译器解释为浮点数。浮点数以 `m × b^e` 的形式存储数值，`m` 是尾数，`b` 是基数（通常为 2），`e` 是指数。这种形式兼顾精度和范围，可以表示较大或较小的数。

类型声明用 `float`。

```cpp
float c = 10.5;
```

`float` 占 4 个字节（32 位），能提供约 **6 到 7 位**有效数字。精度或范围不够时，还有两种更大的类型。

- `double`：占 8 个字节（64 位），能提供约 **15 到 16 位**有效数字。
- `long double`：通常是 16 个字节，精度更高，但不同编译器的实现差异较大。

竞赛代码默认使用 `double`。`float` 只有 6 到 7 位有效数字，处理 `10^9` 量级的数与小数之和时会丢失精度；`double` 的 15 到 16 位有效数字可以满足大多数题目对 `1e-6` 到 `1e-9` 的精度要求。`long double` 的运算速度较慢，只在题目明确要求更高精度时使用。

浮点数只表示近似值。`0.1` 和 `0.2` 在二进制下都无法精确表示，因此

```cpp
double a = 0.1, b = 0.2;
if (a + b == 0.3) { /* 不会进来 */ }
```

上面的 `if` 不会执行。`0.1 + 0.2` 的结果是 `0.30000000000000004`，不等于 `0.3`。浮点数不能用 `==` 比较是否相等，应设置允许误差 `eps`：

```cpp
const double eps = 1e-9;

if (fabs(a + b - 0.3) < eps) {
    cout << "相等\n";
}
```

也可以定义带容差的比较函数，将 `eps` 和比较逻辑集中在一处：

```cpp
const double eps = 1e-9;

bool equal(double a, double b) { return fabs(a - b) < eps; }
bool less_than(double a, double b) { return a < b - eps; }   // a 明显小于 b
```

比较大小关系时也需要考虑误差。两个理论上相等的数直接比较大小时，结果可能取决于误差方向。严格排序时可以使用上面的 `less_than`，而不是直接使用 `<`。

`fabs` 是标准库头文件 `<cmath>` 提供的数学函数，用于对浮点数取绝对值（`<cmath>` 由 C 标准库的 `<math.h>` 演变而来）。

浮点数可以用科学计数法书写，用 `e` 分隔小数部分和指数部分。

```cpp
double x = 123.456e+3;  // 123.456 × 10^3
double x = 123.456e3;   // 加号可以省略
```

`e` 前后不能有空格。小数部分写成 `0.x` 或 `x.0` 时，其中的 `0` 可以省略，`.3E6` 等同于 `0.3E6`。

## 布尔类型

C++ 有专门的布尔类型 `bool`，取值只有 `true`（真）和 `false`（伪），分别对应整数 `1` 和 `0`。它定义在语言里，不需要包含任何头文件。

```cpp
bool flag = false;
bool ok = true;
```

**`bool` 和整数之间可以隐式转换**。将整数赋给 `bool` 时，非零值转换为 `true`，零转换为 `false`；反向转换时，`true` 对应 `1`，`false` 对应 `0`。

```cpp
bool a = 5;      // 非零，a 为 true
bool b = 0;      // 零，b 为 false
int  x = true;   // x 为 1

if (a) {         // 等价于 if (a == true)
    cout << "yes\n";
}
```

`cout` 默认将 `bool` 按整数输出，即输出 `1` 或 `0`，而不是 `true` 或 `false`。

```cpp
cout << true << '\n';    // 1

cout << boolalpha;       // 设了这个操纵符才打印 true/false
cout << true << '\n';    // true
```

逻辑运算的结果是 `bool`，因此 `x = (a > b)` 中的 `x` 是布尔值。竞赛代码通常使用 `bool` 声明判断类变量，避免使用 `int`，因为 `int` 还可以表示其他取值。

## 字面量的类型

字面量（literal）是代码中直接书写的值。

```cpp
int x = 123;   // x 是变量，123 是字面量
```

编译器也会将字面量写入内存，因此字面量同样具有类型。默认情况下，十进制整数字面量（例如 `123`）是 `int`；超出 `int` 范围后，编译器依次从 `long`、`unsigned long`、`long long`、`unsigned long long` 中选择第一个可以容纳该值的类型。小数（例如 `3.14`）一律是 `double`。

不应依赖这种根据数值范围自动选择类型的规则。第一，类型由数值大小决定，修改同一表达式中的常量可能改变运算宽度；第二，字面量可能被转换为无符号类型。竞赛代码通常显式添加后缀，以固定字面量的类型。

## 字面量后缀

后缀用于指定字面量的类型。

```cpp
int x = 123L;   // long
```

小写 `l` 的效果相同，但大写 `L` 与数字 1 在等宽字体中更易区分，例如 `123l` 和 `1231` 的外观接近。八进制、十六进制也可以添加后缀，如 `020L`、`0x20L`。

常用的后缀如下：

| 后缀 | 作用 |
| --- | --- |
| `f`、`F` | `float` 类型，如 `3.14f` |
| `l`、`L` | 整数是 `long int`，小数是 `long double` |
| `ll`、`LL` | `long long`，如 `3LL` |
| `u`、`U` | `unsigned int`，如 `15U`、`0377U` |

`u` 可以与其他整数后缀组合，大小写和顺序不受限制，`10UL`、`10ULL`、`10LLU` 都合法。

```cpp
long long      a = 1234LL;
unsigned long long b = 1234ULL;

float      x = 3.14f;
double     y = 3.14;
long double z = 3.14L;
```

### `1LL` 为什么总写在最前面

竞赛代码中常用的后缀是 `LL`。它需要添加到**整个表达式中第一个算术操作数**上。以下代码展示了两种写法：

```cpp
int n = 100000;
long long wrong = n * (n + 1);         // 错：右边是 int 运算，先溢出，再赋给 long long
long long right = 1LL * n * (n + 1);   // 对：n 先被提升为 long long，整体按 64 位算
```

`wrong` 的错误源于赋值时“先计算右侧，再转换类型”的顺序。`n * (n + 1)` 在右侧独立求值，两个操作数都是 `int`，结果也是 `int`。`10^5 × 10^5 + 10^5` 超过 21 亿，计算过程中已经发生溢出，之后将溢出的结果赋给 `long long` 无法恢复原值。

正确写法需要让表达式**从第一个操作数起**按 64 位计算。写成 `1LL * n` 后，`n` 被提升为 `long long`，后续乘法和加法都按 64 位进行。

位移运算中也经常出现同类错误：

```cpp
long long bad  = 1 << 40;      // 错：1 是 int，左移 40 位是未定义行为
long long good = 1LL << 40;    // 对：1LL 是 long long，结果约 1.1 × 10^12
```

`int` 只有 32 位，将 `1` 左移 40 位属于未定义行为（见下一节）。`1LL << 40` 是竞赛代码中表示 `2^40` 等较大常量的标准写法，`1LL << k` 还可以用于生成位掩码。

## 溢出

每种类型都有取值范围的上下界。数值超出该范围时，需要更多二进制位表示，这种情况称为**溢出**：超过最大值称为向上溢出（overflow），小于最小值称为向下溢出（underflow）。

有符号整数和无符号整数的溢出处理方式不同。

### 无符号数：回绕

无符号整数的运算是**模运算**，超出范围时会“回绕”。该行为由标准明确规定，程序可以依赖这一规则。

```cpp
unsigned char x = 255;
x = x + 1;
cout << (int)x << '\n';   // 0
```

`255` 的二进制是 `11111111`，加 `1` 得到 `100000000`。一个字节无法存储最高位，因此最高位被舍弃，结果为 `0`。

```cpp
unsigned int ui = UINT_MAX;   // 4,294,967,295
ui++;
cout << ui << '\n';           // 0
ui--;
cout << ui << '\n';           // 4,294,967,295
```

减法也遵循这一规则：`0 - 1` 会得到 `UINT_MAX`。该性质可能导致死循环：

```cpp
for (unsigned int i = n; i >= 0; --i) { /* 死循环 */ }
```

`i` 是 `unsigned int`，最小值为 `0`。当 `i` 等于 `0` 时再减 `1`，结果不是 `-1`，而是 `UINT_MAX`，因此循环条件 `i >= 0` 始终成立。需要从 `n` 递减到 `0` 时，可以使用 `int` 作为循环变量，或者将循环写成 `for (int i = n; i >= 0; --i)`。

### 有符号数：未定义行为

有符号整数溢出**不是“回绕”，而是未定义行为**（undefined behavior，UB）。

标准没有规定 `int` 溢出的结果。编译器可以假设溢出不会发生，并据此进行优化，因此同一段代码在不同优化等级或编译器下的行为可能不同。程序不能依赖有符号溢出后“变成负数”或“绕回去”的行为。

```cpp
int x = INT_MAX;
x = x + 1;   // 未定义行为，不是 -2147483648
```

有符号溢出还可能影响编译器优化。编译器假设 `int` 变量持续递增时不会溢出，因此可能将 `for (int i = 0; i <= n; i++)` 视为一定会结束的循环；当 `n` 等于 `INT_MAX` 时，程序行为无法预测。

有符号溢出必须通过设计规避，不能依赖其回绕行为。需要回绕效果时，应使用 `unsigned`。

### 避免溢出

写表达式前估算上界，可以提前避免溢出。

首先估算数值大小。题目约束通常会给出范围，可以将最大值代入计算：`n` 最大为 `10^5`、每个数最大为 `10^9` 时，“求和”的上界是 `10^14`，必须使用 `long long`；`n` 最大为 `10^6` 时，`n × n` 是 `10^12`，同样需要使用 64 位类型。

其次检查**中间结果**，而不只检查最终结果。上述 `n * (n + 1)` 是典型示例：即使变量声明为 `long long`，溢出也可能发生在赋值之前。

二分查找的中点计算也可能发生溢出：

```cpp
int l = 0, r = INT_MAX;
int mid = (l + r) / 2;          // 危险：l + r 可能溢出
int mid = l + (r - l) / 2;      // 安全：差值不会超过 r 的范围
```

`(l + r)` 是两个 `int` 相加，可能溢出；`l + (r - l) / 2` 可以避免该问题。这是竞赛代码中计算中点的标准写法。

比较结果是否超出范围时，不能先执行可能溢出的运算：

```cpp
unsigned int ui, sum;

// 错：sum + ui 已经回绕了，永远不会大于 UINT_MAX
if (sum + ui > UINT_MAX) too_big();

// 对：把加法移到另一边，用减法判断
if (ui > UINT_MAX - sum) too_big();
```

另一种典型错误是在无符号数执行减法后判断正负：

```cpp
unsigned int i = 5, j = 7;
if (i - j < 0) cout << "negative\n";   // 永远不会输出
else           cout << "positive\n";   // 会走这里
```

`i - j` 的结果也是无符号类型，最小值为 `0`，不可能小于 `0`，因此只会执行 `else` 分支。比较大小时应直接使用 `if (j > i)`。

## sizeof 运算符

`sizeof` 返回某个类型或某个值占用的字节数。参数可以是类型，也可以是变量或具体的值。

```cpp
int x = sizeof(int);   // 类型：通常是 4

int i;
sizeof(i);             // 变量：与上一行结果相同

sizeof(3.14);          // 数值：浮点字面量是 double，所以返回 8
```

**`sizeof` 的返回值类型是 `size_t`，一个无符号整数类型**。这一特性会导致有符号数与无符号数的混合运算问题。

大小比较中包含 `size_t` 时，需要处理符号差异。以下代码的判断结果为假：

```cpp
int a = -5;
if (a < sizeof(int)) {   // 判断为假
    // 不会执行
}
```

`a` 是 `int`（有符号），`sizeof(int)` 是 `size_t`（无符号）。混合运算时，有符号的 `a` 会转换为无符号类型，`-5` 随之变成接近 `SIZE_MAX` 的正数，因此 `a < sizeof(int)` 为假。这是上一节所述“有符号与无符号混合运算”的典型结果。

循环变量、下标和计数变量可以统一使用 `int` 或 `long long`，避免使用 `size_t`。将 `sizeof` 的结果与 `int` 比较时，应先转换为同一类型。容器的 `size()` 会返回 `size_t`，相关规则见后面的“混合类型的运算”。

输出 `size_t` 时，`cout` 可以直接识别其类型。使用 `printf` 时，应使用占位符 `%zu`（或 `%zd`），它对应 `size_t` 类型的值：

```cpp
printf("%zu\n", sizeof(int));
```

`sizeof` 在竞赛代码中常用于计算数组元素个数：

```cpp
int a[100];
int n = sizeof(a) / sizeof(a[0]);   // 100
```

使用 `vector` 时不需要该计算，`a.size()` 返回元素个数。

## 类型的自动转换

C++ 在多种情况下会自动转换类型。以下规则会影响前面几节介绍的符号和溢出问题。

### 赋值运算

赋值运算符会将右侧的值转换为左侧变量的类型。

（1）**浮点数赋给整数变量**。 直接**丢弃小数部分**，不是四舍五入。

```cpp
int x = 3.14;    // x 是 3
int y = 12.99;   // y 是 12，不是 13
```

转换会直接丢弃小数部分，因此应避免将浮点数赋给整数变量。

（2）**整数赋给浮点变量**。 自动转为浮点数。

```cpp
double y = 12 * 2;   // y 是 24.0
```

（3）**窄类型赋给宽类型**。 整数会进行类型提升，例如 `char`、`short` 参与运算或赋给 `int` 时会先提升为 `int`。

（4）**宽类型赋给窄类型**。 会发生截值（truncation），多余的二进制位会被舍弃，结果可能不符合预期。

```cpp
int i = 321;
char ch = i;   // ch 是 65
```

`321` 的二进制是 `101000001`，共 9 位；`char` 只能容纳 8 位，因此最高位被舍弃，留下 `01000001`，即十进制的 `65`（字符 `'A'`）。浮点数赋给整数时也会发生截值，小数部分会直接被舍弃：

```cpp
double pi = 3.14159;
int i = pi;    // i 是 3
```

### 混合类型的运算

不同类型的值一起运算，必须先统一类型。规则是：

- 整数与浮点数混合时，整数转为浮点数。
- 不同的浮点类型混合时，宽度小的转为宽度大的（`float` → `double` → `long double`）。
- 不同的整数类型混合时，宽度小的提升为宽度大的；**有符号类型和无符号类型共同运算时，有符号类型会被转换为无符号类型**。

最后一条是前述有符号数与无符号数混合运算问题的共同来源。`int` 与 `size_t` 共同运算时，`int` 会被转换为无符号类型，负数会变成一个较大的正数。标准容器的长度比较需要处理这一问题：

```cpp
vector<int> v = {1, 2, 3, 4, 5};

// 危险：i 是 int，v.size() 是 size_t
for (int i = 0; i < v.size(); i++) { /* ... */ }

// 安全：全程用 int 存长度
int n = v.size();
for (int i = 0; i < n; i++) { /* ... */ }
```

`i < v.size()` 中的 `i` 会转换为 `size_t`。上述正向循环中的 `i` 始终非负，因此不会产生异常；如果循环中出现 `i - 1`，或者循环变量可能变成负数，`-1` 会被转换为 `SIZE_MAX`，从而导致程序行为错误。

应避免混合使用有符号数和无符号数。容器长度和下标等值可以先存入 `int` 或 `long long` 变量，再参与运算。

### 整数类型的运算

两个同类型的整数运算，结果通常仍是同一类型。但存在一个例外：**宽度小于 `int` 的类型，运算结果会自动提升为 `int`**。

```cpp
unsigned char a = 66;
if ((-a) < 0) cout << "negative\n";   // 会输出 negative
else          cout << "positive\n";
```

`a` 是无符号字符，其取值不小于 `0`，但 `-a` 已经不是 `unsigned char`：它先提升为 `int`，结果为 `-66`，因此判断成立。同样的规则适用于以下代码：

```cpp
unsigned char a = 1, b = 255, c = 255;
if ((a - 5) < 0)  cout << "yes\n";   // 输出 yes，a - 5 提升为 int，得到 -4
if ((b + c) > 300) cout << "yes\n";  // 输出 yes，b + c 提升为 int，得到 510
```

两个条件在提升为 `int` 后都成立，结果分别为 -4 和 510。如果按照 8 位无符号类型计算，`a - 5` 会回绕为 `252`，`b + c` 会回绕为 `254`，两个判断的结果都会改变。`char`、`short`、`unsigned char` 参与计算时，应先按提升为 `int` 后的类型分析结果。

### 函数

函数的参数和返回值，也会自动转成函数定义里指定的类型。

```cpp
int dostuff(int, unsigned char);

char m = 42;
unsigned short n = 43;
long long c = dostuff(m, n);   // m、n 会先转成 int 和 unsigned char
```

返回值同理：

```cpp
char func() {
    int a = 42;
    return a;   // 转成 char 返回
}
```

函数返回类型与实际数值范围不匹配也会导致错误。如果函数返回类型是 `int`，但函数中计算的值需要 64 位表示，溢出会在 `return` 时发生。函数返回类型应根据可能出现的最大值选择；无法确定时可以使用 `long long`。

## 类型的显式转换

显式转换用于明确指定目标类型。

C++ 提供了 `static_cast`，写法是把目标类型放进尖括号：

```cpp
static_cast<int>(3.14)
```

圆括号形式也能完成同样的转换，两种写法如下：

```cpp
(int)3.14            // C 风格
static_cast<int>(3.14)   // C++ 风格
```

两者都能将值转换为指定类型，通常使用 `static_cast`，原因有两点：该写法可以明确表示类型转换；它只允许编译器认可的转换，而 `(int)` 形式允许的转换范围更广，编译器可能无法阻止错误转换。该转换属于语言本身，不需要包含头文件。

以下是两个示例：

```cpp
unsigned char ch = 66;
static_cast<unsigned char>(ch);      // 转成无符号字符类型

long y = static_cast<long>(10) + 12; // 把 10 显式转成 long
```

上面的转换不影响结果，因为赋值运算符会将右侧转换为左侧类型。显式转换主要用于**表达式内部**，典型示例是整数除法：

```cpp
int a = 7, b = 2;

double wrong = a / b;                      // 3.0：两个 int 相除，先得到 3，再转 double
double right = static_cast<double>(a) / b; // 3.5：a 先转 double，除法按浮点做
```

第一种写法中的 `a / b` 是两个 `int` 的除法，`3.5` 的小数部分被舍弃，之后转换为 `double` 也无法恢复。第二种写法将**其中一个操作数**转换为 `double`，另一个操作数会自动转换，整个除法按浮点运算执行。

`(double)a / b` 和 `static_cast<double>(a) / b` 的效果完全相同。竞赛代码中两种形式都存在，同一份代码通常统一使用一种形式。

显式转换不能解决溢出，也不能提高浮点数精度，它只改变值的类型。其作用是明确转换意图，而不是修复其他类型错误。

## 可移植类型

`short`、`int`、`long` 的宽度取决于具体实现，在不同机器上可能不同。需要精确宽度时，可以使用标准库头文件 `<cstdint>` 提供的一组长度确定的类型别名（`<cstdint>` 由 C 标准库的 `<stdint.h>` 演变而来）。

（1）**精确宽度类型**，宽度完全确定。

- `int8_t`、`int16_t`、`int32_t`、`int64_t`：8、16、32、64 位有符号整数。
- `uint8_t`、`uint16_t`、`uint32_t`、`uint64_t`：对应宽度的无符号整数。

这些是别名，具体对应的底层类型由编译器决定。例如，某个平台上的 `int` 是 32 位时，`int32_t` 指向 `int`；如果 `long` 是 32 位，则 `int32_t` 指向 `long`。

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int32_t x32 = 45933945;
    cout << x32 << '\n';
    return 0;
}
```

（2）**最小宽度类型**，保证宽度不少于指定位数：`int_least8_t`、`uint_least16_t`、`int_least64_t` 等。

（3）**最快的最小宽度类型**，在满足宽度要求的前提下取运算最快的类型：`int_fast8_t`、`uint_fast32_t` 等。某些机器对特定宽度的数据运算更快，这类别名就是为此准备的。

（4）**能存放指针的整数类型**：`intptr_t`（有符号）、`uintptr_t`（无符号）。

（5）**最大宽度整数类型**：`intmax_t`、`uintmax_t`，宽度比 `long long` 和 `unsigned long` 还大。

这些类型在竞赛代码中较少使用，因为 `int` 和 `long long` 已经覆盖全部需求，而 `int32_t` 等名称较长。了解这些类型有两个作用：阅读相关代码时能够识别类型含义；遇到明确要求“输出一个 32 位无符号整数”的题目时，`uint32_t` 可以准确表达意图。竞赛代码仍然优先使用 `int` 和 `long long`。
